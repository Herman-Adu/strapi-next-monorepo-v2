## The $50,000 Question I Ask Before Every Feature

**Scenario:** Your startup needs user authentication.

**Option A (Buy):** Auth0 - $23/month, 2-hour integration  
**Option B (Build):** Custom auth - $0/month, 80-hour implementation

**Which do you choose?**

**Wrong answer:** "Always buy" or "Always build"  
**Right answer:** "It depends on 7 factors"

**This article is the framework I use to make this decision every time.**

---

## The Real Costs (Beyond Price Tags)

### Total Cost of Ownership (TCO)

Most developers only see upfront costs. Here's what they miss:

```typescript
type TotalCost = {
  // Visible costs
  subscriptionFee: number
  implementationTime: number

  // Hidden costs (often 3-5x visible costs)
  learningCurve: number
  maintenanceBurden: number
  vendorLockIn: number
  migrationRisk: number
  technicalDebt: number
  scalingCosts: number
}
```

**Example: CMS Decision**

| Cost Type                | Build Custom     | Buy (Contentful)   | Strapi (Open Source) |
| ------------------------ | ---------------- | ------------------ | -------------------- |
| **Initial Setup**        | 200 hours        | 10 hours           | 20 hours             |
| **Learning Curve**       | 0 (you built it) | 20 hours           | 15 hours             |
| **Monthly Cost**         | $0               | $300               | $0                   |
| **Annual Cost (Year 1)** | $20K labor       | $3,600 + $1K labor | $1,500 labor         |
| **Maintenance**          | 40 hours/year    | 5 hours/year       | 10 hours/year        |
| **Vendor Lock-in Risk**  | None             | High               | None (self-hosted)   |
| **Migration Difficulty** | N/A              | Very hard          | Easy (export/import) |
| **10-Year TCO**          | $44K             | $39K               | $6K                  |

**Winner:** Strapi (open-source middle ground)

**Why?** Low cost + low lock-in + manageable maintenance.

## The Decision Framework (7 Factors)

### 1. Core Business Value

**Question:** Is this feature your competitive advantage?

#### ✅ Build When:

- **Unique to your business model**  
  Example: Spotify's recommendation algorithm, Airbnb's pricing engine
- **Differentiates you from competitors**  
  Example: Notion's block-based editor, Figma's real-time collaboration
- **Directly generates revenue**  
  Example: Stripe's payment processing, Shopify's checkout flow

#### 🛒 Buy When:

- **Commodity feature everyone has**  
  Example: User authentication, email delivery, payment processing
- **No competitive advantage**  
  Example: Analytics, monitoring, error tracking
- **Well-solved by existing tools**  
  Example: CMS, search, CDN

**Real Example (My Project):**

| Feature            | Decision        | Reasoning                                  |
| ------------------ | --------------- | ------------------------------------------ |
| **Page Builder**   | BUILD           | Core differentiator, unique requirements   |
| **User Auth**      | BUY (NextAuth)  | Commodity, no advantage                    |
| **CMS Backend**    | MIDDLE (Strapi) | Customizable but not from scratch          |
| **Email Delivery** | BUY (Mailgun)   | Commodity, deliverability expertise needed |
| **Image Hosting**  | BUY (AWS S3)    | Infrastructure, not expertise              |

### 2. Time to Market

**Question:** How fast do you need this feature?

#### ✅ Build When:

- **You have 3+ months runway**  
  Example: Core product features, foundational architecture
- **Quality over speed matters**  
  Example: Security-critical features, data models
- **Technical debt is acceptable**  
  Example: MVP with plans to refactor later

#### 🛒 Buy When:

- **You need it this week**  
  Example: Landing page, marketing site, analytics
- **Competitor is moving fast**  
  Example: Feature parity requirements
- **Testing market demand**  
  Example: New feature validation before investment

**Time-to-Market Calculation:**

```typescript
function timeToMarket(feature: Feature): Decision {
  const buildTime = estimateBuildHours(feature)
  const integrationTime = estimateIntegrationHours(feature)
  const runwayMonths = calculateRunway()

  const buildWeeks = buildTime / 40 // 40 hours/week
  const buyWeeks = integrationTime / 40

  if (buildWeeks > runwayMonths * 4 * 0.25) {
    return "BUY" // Uses >25% of runway
  }

  if (buyWeeks < 1 && buildWeeks > 4) {
    return "BUY" // 4x speed advantage
  }

  return "EVALUATE_OTHER_FACTORS"
}
```

**Real Example:**

- **Page Builder:** Built (3 months) - Core product, worth the time
- **Contact Form:** Bought (Formspree, 1 hour) - Not differentiator
- **Analytics:** Bought (Vercel Analytics, 30 min) - Need data immediately

### 3. Maintenance Burden

**Question:** Who will maintain this long-term?

#### ✅ Build When:

- **You have ongoing development resources**  
  Example: Team of 3+ engineers
- **Feature is stable (won't change much)**  
  Example: Data models, API contracts
- **You enjoy maintaining this type of code**  
  Example: Developer tools, CLI tools

#### 🛒 Buy When:

- **Solo developer with limited time**  
  Example: Most solo projects
- **Feature requires constant updates**  
  Example: Security patches, OAuth providers
- **Expertise outside your domain**  
  Example: Video encoding, email deliverability, CDN optimization

**Maintenance Cost Matrix:**

| Feature Type            | Annual Maintenance                                | Who Handles     |
| ----------------------- | ------------------------------------------------- | --------------- |
| **Auth System**         | 80+ hours (security patches, OAuth changes)       | Auth0 handles   |
| **CMS (Strapi)**        | 10-20 hours (upgrades, plugins)                   | You handle      |
| **Email Delivery**      | 100+ hours (blacklist management, deliverability) | Mailgun handles |
| **Custom Page Builder** | 40 hours (bug fixes, features)                    | You handle      |
| **Database**            | 5-10 hours (backups, minor issues)                | You handle      |

**Real Decision:**

- **Built:** Strapi CMS (manageable 10-20 hours/year maintenance)
- **Bought:** Email delivery (100+ hours outsourced to Mailgun)
- **Built:** Page builder (domain expertise, under control)

---

### 4. Vendor Lock-In Risk

**Question:** How hard is it to leave this vendor?

#### ✅ Build When:

- **Migration would be catastrophic**  
  Example: Core data models, business logic
- **Vendor has pricing control**  
  Example: Per-user pricing that scales badly
- **Vendor could shut down**  
  Example: Small startups, unproven tools

#### 🛒 Buy When:

- **Standard export formats exist**  
  Example: CSV, JSON, SQL dumps
- **Multiple vendors offer same service**  
  Example: Email (Mailgun, SendGrid, SES)
- **Migration cost is acceptable**  
  Example: <2 weeks developer time

**Lock-In Risk Assessment:**

| Service        | Lock-In Risk | Migration Difficulty        | Alternative Vendors       |
| -------------- | ------------ | --------------------------- | ------------------------- |
| **Contentful** | HIGH         | Very hard (proprietary API) | Medium (Strapi, Sanity)   |
| **Strapi**     | LOW          | Easy (self-hosted, export)  | Many (Payload, Directus)  |
| **Auth0**      | MEDIUM       | Medium (OAuth standard)     | Many (Clerk, Supabase)    |
| **Vercel**     | LOW          | Easy (Next.js portable)     | Many (Netlify, AWS)       |
| **AWS S3**     | LOW          | Easy (standard API)         | Many (Cloudflare R2, GCS) |
| **Heroku**     | LOW          | Medium (Procfile standard)  | Many (Railway, Render)    |

**Red Flags (High Lock-In):**

- Proprietary data formats
- No export API
- Vendor-specific code required
- Single vendor (no alternatives)
- Complex migration process documented as "not recommended"

**Green Flags (Low Lock-In):**

- Standard APIs (REST, GraphQL)
- Export functionality built-in
- Open-source option available
- Multiple competing vendors
- Migration guides exist

### 5. Customization Requirements

**Question:** Will you need to customize this heavily?

#### ✅ Build When:

- **Your requirements are unique**  
  Example: Industry-specific workflows, novel UX patterns
- **SaaS tools don't offer needed flexibility**  
  Example: Multi-tenancy, custom data models
- **You'll hit customization limits quickly**  
  Example: Workflow automation, complex business rules

#### 🛒 Buy When:

- **Standard use case**  
  Example: Blog, e-commerce store, SaaS dashboard
- **SaaS covers 90% of needs**  
  Example: Analytics, monitoring, email
- **Customization isn't worth the cost**  
  Example: Small tweaks vs 100+ hours development

**Customization Spectrum:**

```
Low Customization           Medium Customization         High Customization
─────────────────────────────────────────────────────────────────────────
   BUY (SaaS)               OPEN SOURCE (Strapi)           BUILD CUSTOM

Examples:                   Examples:                      Examples:
- Google Analytics          - Strapi CMS                  - Spotify algorithm
- Mailgun                   - WordPress                   - Figma editor
- Stripe                    - Ghost                       - Notion blocks
- Auth0                     - Supabase                    - Custom ERP
```

**Real Example (CMS Decision):**

| Option         | Customization      | Cost         | Decision         |
| -------------- | ------------------ | ------------ | ---------------- |
| **Contentful** | Low (SaaS limits)  | $300/month   | ❌ Too rigid     |
| **Custom CMS** | Infinite           | 400+ hours   | ❌ Too expensive |
| **Strapi**     | High (open source) | 0 + 20 hours | ✅ Sweet spot    |

**Why Strapi won:** Customizable backend + admin UI included + self-hosted.

### 6. Learning Curve

**Question:** How long to become productive?

#### ✅ Build When:

- **You already have the expertise**  
  Example: Building React components (if you know React)
- **Technology is simple/well-documented**  
  Example: REST APIs, SQL databases
- **Learning is strategic investment**  
  Example: Core technologies you'll use for years

#### 🛒 Buy When:

- **Steep learning curve (weeks/months)**  
  Example: Kubernetes, machine learning, video encoding
- **Technology outside your expertise**  
  Example: DevOps, security, infrastructure
- **One-time use (not worth learning)**  
  Example: PDF generation, image processing

**Learning Curve Estimates:**

| Technology               | Time to Productivity | Build vs Buy Decision   |
| ------------------------ | -------------------- | ----------------------- |
| **React**                | 2-3 weeks            | BUILD (reusable skill)  |
| **Next.js**              | 1-2 weeks            | BUILD (strategic)       |
| **Strapi**               | 3-5 days             | BUILD (manageable)      |
| **Kubernetes**           | 3-6 months           | BUY (use Heroku/Vercel) |
| **Video Encoding**       | 6-12 months          | BUY (use Cloudinary)    |
| **Email Deliverability** | 6-12 months          | BUY (use Mailgun)       |
| **OAuth Providers**      | 2-4 weeks            | BUY (use Auth0)         |

**Rule of Thumb:**

- Learning curve <1 week → Consider building
- Learning curve 1-4 weeks → Evaluate other factors
- Learning curve >1 month → Strongly consider buying

---

### 7. Cost at Scale

**Question:** What happens when you 10x?

#### ✅ Build When:

- **SaaS pricing scales with usage**  
  Example: Per-user pricing, per-API-call, per-GB
- **You'll hit pricing tiers quickly**  
  Example: 100 users → 10,000 users in 6 months
- **Fixed-cost infrastructure is cheaper**  
  Example: Self-hosted vs managed SaaS

#### 🛒 Buy When:

- **Fixed pricing (flat monthly fee)**  
  Example: Unlimited users, unlimited requests
- **Usage-based but predictable**  
  Example: Email (know sending volume)
- **Infrastructure costs exceed SaaS**  
  Example: CDN (AWS CloudFront vs Cloudflare)

**Cost Scaling Example (Auth System):**

| Users       | Auth0 Cost   | Self-Hosted Cost        | Winner      |
| ----------- | ------------ | ----------------------- | ----------- |
| **100**     | $23/month    | $500 setup + $0/month   | Auth0       |
| **1,000**   | $240/month   | $500 setup + $25/month  | Auth0       |
| **10,000**  | $1,200/month | $500 setup + $50/month  | Self-Hosted |
| **100,000** | $8,000/month | $500 setup + $200/month | Self-Hosted |

**Break-even:** ~15,000 users (18 months at 10% monthly growth)

**Decision:** Use Auth0 early, migrate to self-hosted at scale.

## The Decision Matrix

### How to Decide in 5 Minutes

**Step 1: Score each factor (0-10)**

| Factor              | Score   | Weight |
| ------------------- | ------- | ------ |
| Core business value | \_\_/10 | 3x     |
| Time to market      | \_\_/10 | 2x     |
| Maintenance burden  | \_\_/10 | 2x     |
| Vendor lock-in risk | \_\_/10 | 2x     |
| Customization needs | \_\_/10 | 1.5x   |
| Learning curve      | \_\_/10 | 1x     |
| Cost at scale       | \_\_/10 | 1.5x   |

**Step 2: Calculate weighted score**

```typescript
function calculateBuildScore(scores: Scores): number {
  return (
    (scores.coreValue * 3 +
      scores.timeToMarket * 2 +
      scores.maintenance * 2 +
      scores.vendorRisk * 2 +
      scores.customization * 1.5 +
      scores.learningCurve * 1 +
      scores.costAtScale * 1.5) /
    13
  ) // Sum of weights
}
```

**Step 3: Interpret result**

- **8-10:** Strong BUILD candidate
- **5-7:** MIDDLE GROUND (open source, low-code)
- **0-4:** Strong BUY candidate

## The Middle Ground: Open Source

**Best of both worlds:**

✅ No subscription fees (like building)  
✅ Pre-built functionality (like buying)  
✅ Full customization (like building)  
✅ Community support (like buying)

**When to choose open source:**

- **Need customization but not from scratch**  
  Example: Strapi CMS, Ghost blog, Supabase backend
- **Want control without SaaS lock-in**  
  Example: Self-hosted analytics (Plausible, Umami)
- **Have time to learn but not build from zero**  
  Example: Most developer tools

**Open-Source Examples:**

| Category      | Open Source Option      | SaaS Alternative   | Build Custom |
| ------------- | ----------------------- | ------------------ | ------------ |
| **CMS**       | Strapi, Payload         | Contentful, Sanity | 400+ hours   |
| **Backend**   | Supabase                | Firebase           | 600+ hours   |
| **Auth**      | NextAuth, Supabase Auth | Auth0, Clerk       | 300+ hours   |
| **Analytics** | Plausible, Umami        | Google Analytics   | 200+ hours   |
| **Blog**      | Ghost                   | Medium, Substack   | 150+ hours   |

**My Stack:**

- ✅ Strapi (open source CMS)
- ✅ NextAuth (open source auth)
- ✅ Next.js (open source framework)
- ✅ PostgreSQL (open source database)
- 🛒 Mailgun (SaaS email delivery)
- 🛒 AWS S3 (SaaS object storage)

**Pattern:** Open source for core features, SaaS for infrastructure.

## Common Mistakes

### Mistake 1: "Always Build" Mentality

**Symptom:** Reinventing every wheel, slow progress, technical debt

**Example:** Building custom auth system instead of using NextAuth

**Cost:** 300+ hours (vs 2 hours integration)

**Fix:** Default to "buy" for commodity features, only build when justified.

---

### Mistake 2: "Always Buy" Mentality

**Symptom:** Monthly costs spiral, vendor lock-in, customization limits

**Example:** Using Contentful for CMS ($300/month + rigid data model)

**Cost:** $3,600/year + migration difficulty

**Fix:** Evaluate open-source options before SaaS.

---

### Mistake 3: Ignoring Total Cost of Ownership

**Symptom:** Choosing based on upfront cost alone

**Example:** Building custom CMS (0 upfront) without considering 40+ hours/year maintenance

**Cost:** $44K over 10 years (vs $6K for Strapi)

**Fix:** Calculate 3-5 year TCO, not just year 1.

---

### Mistake 4: Premature Optimization

**Symptom:** Building for scale you don't have yet

**Example:** Self-hosting everything to "save money at scale" with 10 users

**Cost:** Weeks of DevOps work for hypothetical future savings

**Fix:** Use SaaS early, migrate to self-hosted when you actually scale.

---

### Mistake 5: Fear of Technical Debt

**Symptom:** Over-engineering, analysis paralysis, slow shipping

**Example:** Spending 3 months on "perfect" architecture before launching

**Cost:** Missed market opportunity, competitor moves first

**Fix:** Ship fast with SaaS, refactor/rebuild when you have revenue.

## Key Takeaways

✅ **No universal answer** - "Build vs buy" depends on 7 factors  
✅ **Use the decision matrix** - Score each factor, calculate weighted result  
✅ **Consider open source** - Best of both worlds (customization + pre-built)  
✅ **Think long-term** - 3-5 year TCO, not just year 1  
✅ **Default to "buy" for commodity** - Auth, email, analytics, CDN  
✅ **Build your competitive advantage** - Core features that differentiate you  
✅ **Migration is possible** - Start with SaaS, migrate to self-hosted at scale

**Bottom line:** Build what makes you unique. Buy everything else.

## Next Steps

**If you're making this decision right now:**

1. List all features you need
2. Score each using the decision matrix
3. Identify patterns (most should be "buy" or open source)
4. Build only the 2-3 core differentiators
5. Revisit decisions every 6-12 months (as you scale)

**If you're stuck with bad decisions:**

1. Calculate actual TCO of current approach
2. Estimate migration cost to better option
3. If migration cost < 1 year of current waste → migrate
4. Document lessons learned for future
