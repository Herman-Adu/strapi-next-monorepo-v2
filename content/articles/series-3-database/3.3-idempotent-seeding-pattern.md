## The Pattern That Prevents $3,000 Disasters

After accidentally deleting 203 entities and 331 assets with a single command ([read that story here](./3.2-strapi-export-saved-3000.md)), I learned the hard way:

**The same seed script that's safe in CI will destroy your development database.**

The problem? Most tutorials show you one seed script:

```typescript
// ❌ The dangerous pattern everyone copies
export default async ({ strapi }) => {
  // Delete all existing data first
  await strapi.db.query("api::page.page").deleteMany()

  // Then create test data
  await strapi.db.query("api::page.page").create({ data: pageData })
}
```

This works great in CI (fresh database every run). But in development (where you've been building content for weeks), it's a **data loss disaster waiting to happen**.

Here's the pattern I built instead: **idempotent seed scripts** that check if content exists before creating it, preventing data loss across all environments.

## The Problem: Destructive vs Safe Seeding

### What CI Needs (Destructive)

**Characteristics:**

- ✅ Fresh database every run
- ✅ No existing content to preserve
- ✅ Isolation guaranteed (containers)
- ✅ Delete-then-create is safe

**Example CI workflow:**

```yaml
# .github/workflows/e2e-tests.yml
- name: Start Strapi
  run: docker-compose up -d

- name: Seed Test Data
  run: yarn seed:e2e # Destructive is fine here

- name: Run E2E Tests
  run: yarn test:e2e

- name: Teardown
  run: docker-compose down -v # Destroys container
```

**Why destructive works:** Container gets destroyed anyway. No data to lose.

### What Development Needs (Safe)

**Characteristics:**

- ❌ Has valuable content (days/weeks of work)
- ❌ Shared across manual testing
- ❌ Accumulates real data over time
- ❌ Delete-then-create destroys everything

**Development workflow:**

```bash
# Developer's daily workflow
yarn dev                # Start dev server
yarn seed:e2e:safe      # Create ONLY test page (preserve others)
yarn test:e2e:local     # Run E2E tests locally
```

**Why safe is critical:** Losing your development content costs hours of recreation.

## The Two-Script System

After my data loss incident, I created **two separate scripts** for different environments:

### Script 1: Destructive (CI Only)

**File:** `apps/strapi/database/seeds/e2e-test-data.ts`

**When to use:** GitHub Actions, GitLab CI, automated testing

**Safety level:** ⚠️ **DESTRUCTIVE** - Only use in throwaway environments

**Key characteristic:** Deletes existing content to ensure clean state

### Script 2: Safe (Local Development)

**File:** `apps/strapi/database/seeds/e2e-test-data-safe.ts`

**When to use:** Local development, manual testing, anytime you have existing content

**Safety level:** ✅ **SAFE** - Can run multiple times without data loss

**Key characteristic:** Checks if content exists before creating (idempotent)

## Idempotent Pattern: Check-Then-Update

### What Is Idempotency?

**Definition:** An operation that produces the same result no matter how many times you run it.

**Examples:**

- ✅ **Idempotent:** Setting a value (`x = 5` → always 5)
- ❌ **Not idempotent:** Incrementing a value (`x++` → different each time)

**In database seeding:**

- ✅ **Idempotent:** Check if page exists → update or create
- ❌ **Not idempotent:** Delete all → create (destroys on each run)

### The Safe Pattern Implementation

```typescript
// ✅ SAFE: Idempotent seed script
export default async ({ strapi }) => {
  console.log("🌱 Starting SAFE E2E test data seeding...")

  // 1. CHECK IF CONTENT ALREADY EXISTS
  const existingPages = await strapi.documents("api::page.page").findMany({
    filters: {
      slug: { $eq: "e2e-test-page" },
      locale: { $eq: "en" },
    },
    locale: "en",
  })

  let e2eTestPage

  // 2. UPDATE EXISTING vs CREATE NEW
  if (existingPages && existingPages.length > 0) {
    // Content exists - UPDATE it
    console.log("✅ E2E test page already exists - updating...")

    e2eTestPage = await strapi.documents("api::page.page").update({
      documentId: existingPages[0].documentId,
      data: getE2EPageData(), // Fresh test data
      locale: "en",
    })

    console.log(`✅ Updated E2E test page (ID: ${e2eTestPage.documentId})`)
  } else {
    // Content doesn't exist - CREATE it
    console.log("📄 Creating new E2E test page...")

    e2eTestPage = await strapi.documents("api::page.page").create({
      data: getE2EPageData(),
      locale: "en",
    })

    console.log(`✅ Created E2E test page (ID: ${e2eTestPage.documentId})`)
  }

  // 3. PUBLISH (idempotent operation)
  await strapi.documents("api::page.page").publish({
    documentId: e2eTestPage.documentId,
    locale: "en",
  })

  console.log("✅ E2E test page published successfully")
  console.log("✅ All existing content preserved")
}
```

**Why this is safe:**

- ✅ First run: Creates E2E test page (0 → 1 page)
- ✅ Second run: Updates E2E test page (1 → 1 page, refreshed content)
- ✅ Third run: Updates E2E test page (1 → 1 page, refreshed content)
- ✅ Your other pages: **Never touched**

**Result:** Run it 100 times, your other content stays safe.

## Side-by-Side Comparison

### Destructive Pattern (CI)

```typescript
// ❌ DESTRUCTIVE: e2e-test-data.ts (CI ONLY)
export default async ({ strapi }) => {
  console.log("🌱 Starting E2E test data seeding (DESTRUCTIVE)...")

  // 1. DELETE EVERYTHING (even content you care about)
  console.log("🗑️  Deleting all existing pages...")

  const allPages = await strapi.documents("api::page.page").findMany()

  for (const page of allPages) {
    await strapi.documents("api::page.page").delete({
      documentId: page.documentId,
    })
  }

  // 2. CREATE TEST DATA
  console.log("📄 Creating E2E test page...")

  const e2eTestPage = await strapi.documents("api::page.page").create({
    data: getE2EPageData(),
    locale: "en",
  })

  // 3. PUBLISH
  await strapi.documents("api::page.page").publish({
    documentId: e2eTestPage.documentId,
    locale: "en",
  })

  console.log("✅ E2E test page created")
  console.log("⚠️  All other pages deleted")
}
```

**What this does:**

- ❌ Deletes ALL pages (Landing, About, Services, Contact, etc.)
- ✅ Creates clean E2E test page
- ✅ Perfect for CI (fresh container)
- ❌ **DISASTER for development** (loses all your work)

### Safe Pattern (Development)

```typescript
// ✅ SAFE: e2e-test-data-safe.ts (DEVELOPMENT)
export default async ({ strapi }) => {
  console.log("🌱 Starting SAFE E2E test data seeding...")

  // 1. CHECK IF E2E TEST PAGE EXISTS
  const existingPages = await strapi.documents("api::page.page").findMany({
    filters: { slug: { $eq: "e2e-test-page" } },
  })

  let e2eTestPage

  // 2. UPDATE vs CREATE (only E2E page, nothing else)
  if (existingPages.length > 0) {
    // Update existing E2E page
    e2eTestPage = await strapi.documents("api::page.page").update({
      documentId: existingPages[0].documentId,
      data: getE2EPageData(),
    })
    console.log("✅ Updated E2E test page")
  } else {
    // Create new E2E page
    e2eTestPage = await strapi.documents("api::page.page").create({
      data: getE2EPageData(),
    })
    console.log("✅ Created E2E test page")
  }

  // 3. PUBLISH
  await strapi.documents("api::page.page").publish({
    documentId: e2eTestPage.documentId,
  })

  console.log("✅ E2E test page ready")
  console.log("✅ All existing content preserved")
}
```

**What this does:**

- ✅ Checks if E2E test page exists
- ✅ Updates if exists, creates if not
- ✅ **Never touches other pages** (Landing, About, etc. safe)
- ✅ Safe to run multiple times

## Environment Detection

### Explicit Script Selection (Recommended)

**Best practice:** Use different npm scripts for each environment.

```json
// package.json
{
  "scripts": {
    "seed:e2e": "node scripts/run-seed.js e2e-test-data.ts",
    "seed:e2e:safe": "node scripts/run-seed-safe.js e2e-test-data-safe.ts"
  }
}
```

**Usage:**

```bash
# CI environment (GitHub Actions)
yarn seed:e2e          # Runs destructive script

# Development environment
yarn seed:e2e:safe     # Runs safe script
```

**Advantages:**

- ✅ Explicit (no guessing)
- ✅ Self-documenting (script name tells you what it does)
- ✅ Hard to use wrong one (different commands)

### Automatic Detection (Advanced)

**Alternative:** Detect environment and choose script automatically.

```typescript
// scripts/seed-auto.ts
const isDevelopment = process.env.NODE_ENV === "development"
const isCI = process.env.CI === "true"

if (isCI) {
  console.log("🤖 CI environment detected - using destructive seed")
  await import("./database/seeds/e2e-test-data.ts")
} else if (isDevelopment) {
  console.log("💻 Development environment detected - using safe seed")
  await import("./database/seeds/e2e-test-data-safe.ts")
} else {
  throw new Error("❌ Unknown environment - cannot determine safe seed method")
}
```

**Advantages:**

- ✅ Automatic (developers can't forget)
- ✅ Single command (`yarn seed:e2e`)

**Disadvantages:**

- ❌ Relies on environment variables (can be wrong)
- ❌ Less explicit (harder to understand what will happen)

**Recommendation:** Use explicit scripts. Safety > convenience.

## Package.json Organization

### Clear Naming Convention

```json
{
  "scripts": {
    "// DATABASE SEEDING": "Scripts for populating test/dev data",
    "seed:e2e": "node scripts/run-seed.js e2e-test-data.ts",
    "seed:e2e:safe": "node scripts/run-seed-safe.js e2e-test-data-safe.ts",
    "// WARNING": "seed:e2e is DESTRUCTIVE - use seed:e2e:safe for local dev",

    "// BACKUP & RESTORE": "Database backup utilities",
    "export:all": "strapi export --no-encrypt -f backup.tar.gz",
    "import:all": "strapi import -f backup.tar.gz --force",

    "// E2E TESTING": "End-to-end testing workflows",
    "test:e2e": "playwright test",
    "test:e2e:local": "yarn seed:e2e:safe && playwright test"
  }
}
```

**Key principles:**

1. **Grouped by purpose** (comments separate concerns)
2. **Descriptive names** (`safe` suffix makes it obvious)
3. **Inline warnings** (prevent accidental destructive use)
4. **Compound workflows** (`test:e2e:local` includes safe seeding)

### Documentation in Scripts

Add warnings at the top of destructive scripts:

```bash
#!/bin/bash
# seed-e2e-data.sh

# ⚠️  CI USE ONLY - THIS WILL DELETE ALL DATA ⚠️
# For local development, use: seed-e2e-data-safe.sh

echo "🚨 WARNING: DESTRUCTIVE OPERATION"
echo "This will DROP the entire public schema"
echo "Only use in CI environments with fresh databases"
echo ""
echo "Press Ctrl+C to cancel, or wait 5 seconds..."
sleep 5

# ... destructive operations
```

## Prevention Checklist

### When Creating Seed Scripts

**🔍 Design Phase**

- [ ] Identify if script will be used in CI, dev, or both
- [ ] Determine if existing data needs preservation
- [ ] Decide on destructive vs idempotent approach
- [ ] Plan rollback strategy (backups, versioning)

**💻 Implementation Phase**

- [ ] Use `findMany()` to check if content exists
- [ ] Implement update-or-create pattern for idempotency
- [ ] Add clear logging (what's being created/updated)
- [ ] Include environment detection (if automatic)

**📝 Documentation Phase**

- [ ] Add header comment explaining safety level
- [ ] Document when to use this script vs alternatives
- [ ] Include example commands in comments
- [ ] Warn about destructive operations explicitly

**🧪 Testing Phase**

- [ ] Run script in fresh environment (should create)
- [ ] Run script again (should update, not duplicate)
- [ ] Verify other content untouched (if safe script)
- [ ] Test in both CI and dev environments

### When Running Seed Scripts

**Before Execution**

- [ ] Verify which environment you're in (dev/CI/prod)
- [ ] Check if database has content you care about
- [ ] Confirm script is appropriate for environment
- [ ] Create backup if destructive operation

**During Execution**

- [ ] Watch log output for unexpected deletions
- [ ] Verify script is doing what you expect
- [ ] Stop if anything looks wrong (Ctrl+C)

**After Execution**

- [ ] Verify expected content was created
- [ ] Check other content wasn't affected
- [ ] Test functionality (pages load, APIs work)
- [ ] Document any issues or improvements

## Key Takeaways

### The Idempotent Pattern

**Core concept:** Check if content exists before creating it.

```typescript
// ✅ Safe pattern
const existing = await strapi.documents("api::page.page").findMany({
  filters: { slug: "e2e-test-page" },
})

if (existing.length > 0) {
  // Update
  await strapi.documents("api::page.page").update({
    documentId: existing[0].documentId,
    data: newData,
  })
} else {
  // Create
  await strapi.documents("api::page.page").create({
    data: newData,
  })
}
```

**Benefits:**

- ✅ Safe to run multiple times
- ✅ Never duplicates content
- ✅ Never deletes existing content
- ✅ Works in any environment

### Environment-Specific Scripts

**Use the right tool for the job:**

| Environment | Script Type | Safe? | Use Case                       |
| ----------- | ----------- | ----- | ------------------------------ |
| CI          | Destructive | ✅    | Fresh containers, isolated     |
| Development | Idempotent  | ✅    | Preserves existing work        |
| Production  | Neither     | ✅    | Use proper migrations          |
| Staging     | Idempotent  | ✅    | May have valuable test content |

### Prevention Principles

1. **Explicit > Automatic:** Different scripts for different environments
2. **Warn Early:** Add warnings to destructive operations
3. **Default Safe:** Safe script should be the default in docs
4. **Test Twice:** Run in fresh environment AND with existing content
5. **Backup First:** Create backup before risky operations
