## The 2-Hour Detour Nobody Saw Coming

Fresh PostgreSQL 17 installation. Clean database created. Correct password entered. Everything should work.

Instead:

```bash
Error: password authentication failed for user "strapi_user"
    at Connection.parseE (/node_modules/pg/lib/connection.js:674:13)
```

**The confusing part:** pgAdmin connected fine with the same credentials. Strapi? Nope.

Two hours of debugging later, I discovered the issue wasn't the password—it was the authentication _method_.

---

## What Actually Went Wrong

### The Hidden Mismatch

PostgreSQL 17 introduced a silent but breaking change in default authentication:

**PostgreSQL 15-16 (old default):**

```
Authentication method: MD5
```

**PostgreSQL 17 (new default):**

```
Authentication method: SCRAM-SHA-256
```

Here's what this means in practice:

1. **You create a user** with `CREATE USER strapi_user WITH PASSWORD 'your_password';`
2. **PostgreSQL stores the password** encrypted using... something (you don't specify)
3. **You try to connect** from Strapi
4. **PostgreSQL checks `pg_hba.conf`** for which authentication method to use
5. **Mismatch:** Password stored as MD5, but `pg_hba.conf` says use SCRAM-SHA-256
6. **Result:** Authentication failed ❌

### Why pgAdmin Worked But Strapi Didn't

**pgAdmin** has a checkbox: "Use SCRAM-SHA-256 if available"

- It tries both methods automatically
- Smart fallback behavior
- "Just works" ✅

**Strapi (using `node-postgres` library):**

- Uses whatever `pg_hba.conf` specifies
- No automatic fallback
- Fails if mismatch ❌

## The Fix (Choose Your Poison)

You have two options. Pick based on your environment:

### Option 1: Change pg_hba.conf to MD5 (Development Only)

**⚠️ Use this for:** Local development environments  
**⚠️ Don't use this for:** Production (MD5 is less secure)

#### Windows (PowerShell as Administrator)

**Step 1: Locate pg_hba.conf**

```powershell
# Find PostgreSQL data directory
Get-Service postgresql* | Select-Object Name

# Common location:
# C:\Program Files\PostgreSQL\17\data\pg_hba.conf
```

**Step 2: Open in Notepad as Administrator**

```powershell
Start-Process notepad "C:\Program Files\PostgreSQL\17\data\pg_hba.conf" -Verb RunAs
```

**Step 3: Find and modify these lines (around line 82-83)**

```
# Before (PostgreSQL 17 default):
host    all             all             127.0.0.1/32            scram-sha-256
host    all             all             ::1/128                 scram-sha-256

# After (your change):
host    all             all             127.0.0.1/32            md5
host    all             all             ::1/128                 md5
```

**Step 4: Save and restart PostgreSQL**

```powershell
# Restart service
Restart-Service postgresql-x64-17

# Verify it restarted
Get-Service postgresql-x64-17
# Should show Status: Running
```

#### Linux/Mac

**Step 1: Find pg_hba.conf**

```bash
# Ubuntu/Debian
sudo -u postgres psql -c "SHOW hba_file"
# Output: /etc/postgresql/17/main/pg_hba.conf

# macOS (Homebrew)
psql -U postgres -c "SHOW hba_file"
# Output: /opt/homebrew/var/postgresql@17/pg_hba.conf
```

**Step 2: Edit with sudo**

```bash
# Ubuntu/Debian
sudo nano /etc/postgresql/17/main/pg_hba.conf

# macOS
sudo nano /opt/homebrew/var/postgresql@17/pg_hba.conf
```

**Step 3: Change scram-sha-256 to md5**

```
# Lines to modify (look for localhost connections)
host    all             all             127.0.0.1/32            md5
host    all             all             ::1/128                 md5
```

**Step 4: Restart PostgreSQL**

```bash
# Ubuntu/Debian
sudo systemctl restart postgresql

# macOS (Homebrew)
brew services restart postgresql@17
```

#### Test the Connection

```bash
cd apps/strapi
yarn dev

# Should see:
# Server started on http://localhost:1337 ✅
# No authentication errors ✅
```

### Option 2: Recreate User with SCRAM-SHA-256 (Production)

**✅ Use this for:** Production environments  
**✅ Benefit:** Better security (SCRAM-SHA-256 more resistant to attacks)  
**⚠️ Downside:** More complex setup

#### The Quick Way (Drop Everything)

**⚠️ Warning:** This deletes your database and user. Backup first if you have data!

```sql
-- Connect to postgres database (NOT your application database)
-- In pgAdmin: Right-click postgres database → Query Tool

-- Drop database and user
DROP DATABASE IF EXISTS strapi_dev;
DROP USER IF EXISTS strapi_user;

-- Recreate user (will use SCRAM-SHA-256 by default in PostgreSQL 17)
CREATE USER strapi_user WITH PASSWORD 'your_password';
ALTER USER strapi_user WITH SUPERUSER;

-- Recreate database
CREATE DATABASE strapi_dev OWNER strapi_user;
```

Now the user is stored with SCRAM-SHA-256 encryption, matching the `pg_hba.conf` default.

#### The Safe Way (Keep Existing Data)

If you have data you want to keep:

```sql
-- Step 1: Export your database first
-- In terminal:
pg_dump -U postgres -d strapi_dev -F c -f backup.dump

-- Step 2: In pgAdmin, connected to postgres database:
DROP DATABASE strapi_dev;
DROP USER strapi_user;

-- Step 3: Recreate with SCRAM-SHA-256
CREATE USER strapi_user WITH PASSWORD 'your_password';
ALTER USER strapi_user WITH SUPERUSER;
CREATE DATABASE strapi_dev OWNER strapi_user;

-- Step 4: Restore data
-- In terminal:
pg_restore -U strapi_user -d strapi_dev backup.dump
```

## Understanding the Security Trade-off

### MD5 (Old Default)

**How it works:**

- Password hashed once: `MD5(password + salt)`
- Same password = same hash (with same salt)
- Vulnerable to rainbow table attacks

**When to use:**

- ✅ Local development only
- ✅ Fast to set up
- ✅ Compatible with older tools

**When NOT to use:**

- ❌ Production environments
- ❌ Any internet-accessible database
- ❌ Compliance requirements (PCI, HIPAA, etc.)

### SCRAM-SHA-256 (New Default)

**How it works:**

- Multi-round hashing with salting
- Client-server challenge-response
- Resistant to eavesdropping and rainbow tables

**When to use:**

- ✅ Production environments
- ✅ Any security-sensitive application
- ✅ Compliance requirements

**When NOT to use:**

- Only if you have legacy tool compatibility issues (rare)

## Prevention Checklist

**For New PostgreSQL Installations:**

- [ ] Note PostgreSQL version (17+ uses SCRAM-SHA-256 by default)
- [ ] Decide on authentication method before creating users
  - [ ] Development: MD5 is acceptable (easier)
  - [ ] Production: SCRAM-SHA-256 required (secure)
- [ ] Set `pg_hba.conf` to match your choice
- [ ] Create users AFTER setting authentication method
- [ ] Test connection before building full application
- [ ] Document which method you chose (in README or wiki)

**For Existing Installations:**

- [ ] Check current `pg_hba.conf` settings
- [ ] Verify user password encryption method
- [ ] If mismatch, pick fix strategy (Option 1 or 2)
- [ ] Update documentation with chosen method
- [ ] Share with team (avoid duplicate debugging)

## Common Pitfalls

### ❌ Pitfall #1: Editing the Wrong pg_hba.conf

**Problem:** Multiple PostgreSQL versions installed, editing wrong config file

**Solution:**

```powershell
# Always verify location first
psql -U postgres -c "SHOW hba_file"
# Edit THAT file, not a random one you found
```

### ❌ Pitfall #2: Not Restarting PostgreSQL

**Problem:** Config changes don't take effect until service restarts

**Solution:**

```powershell
# Windows
Restart-Service postgresql-x64-17

# Linux
sudo systemctl restart postgresql

# macOS
brew services restart postgresql@17
```

### ❌ Pitfall #3: Using MD5 in Production

**Problem:** MD5 is vulnerable to attacks, fails security audits

**Solution:**

- Development: MD5 acceptable
- Production: SCRAM-SHA-256 required
- Document this decision clearly

### ❌ Pitfall #4: Forgetting to Backup Before Recreating User

**Problem:** DROP USER deletes all data associated with that user

**Solution:**

```bash
# ALWAYS backup first
pg_dump -U postgres -d your_database -F c -f backup_$(date +%Y%m%d).dump

# Then proceed with user recreation
```

## The Bigger Picture

This isn't just a PostgreSQL quirk—it's a pattern you'll see everywhere:

**Versioned defaults change:**

- PostgreSQL 17: SCRAM-SHA-256 is now default
- Node.js 18+: fetch() API built-in (changed default HTTP library)
- Tailwind v4: CSS-first configuration (changed config file format)

**The Lesson:**
When major version changes happen, check release notes for:

1. New defaults
2. Breaking changes
3. Migration guides

Don't assume "same setup, should work" across versions.
