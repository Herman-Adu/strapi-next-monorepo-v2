# Migrating from Tailwind v3 to v4: The CSS-First Configuration Revolution

**Reading Time:** 10 minutes  
**Difficulty:** Intermediate  
**Last Updated:** December 10, 2025

**SEO Keywords:** tailwind v4 migration, CSS-first configuration, @import tailwindcss, postcss configuration, @plugin directive

## The Configuration File That Vanished

I opened my project one morning ready to migrate to Tailwind v4. Expected a few dependency updates, maybe some breaking changes in utility classes.

Instead, I found this in the migration guide:

> "Tailwind CSS v4.0 is a CSS-first framework. Configuration now lives in CSS using @import and @plugin directives."

**Translation:** My 100-line `tailwind.config.js` file? Gone. Replaced by 10 lines of CSS.

After 3 hours of migration, here's what I learned: This isn't just a version bump—it's a fundamental rethinking of how Tailwind configuration works. And it's **dramatically better**.

---

## What Actually Changed (The Big Picture)

### Tailwind v3: JavaScript Configuration

```javascript
// tailwind.config.js (v3)
/** @type {import('tailwindcss').Config} */
module.exports = {
  darkMode: ["class"],
  content: [
    "./pages/**/*.{ts,tsx}",
    "./components/**/*.{ts,tsx}",
    "./app/**/*.{ts,tsx}",
    "./src/**/*.{ts,tsx}",
  ],
  prefix: "",
  theme: {
    container: {
      center: true,
      padding: "2rem",
      screens: {
        "2xl": "1400px",
      },
    },
    extend: {
      colors: {
        border: "hsl(var(--border))",
        input: "hsl(var(--input))",
        ring: "hsl(var(--ring))",
        background: "hsl(var(--background))",
        foreground: "hsl(var(--foreground))",
        primary: {
          DEFAULT: "hsl(var(--primary))",
          foreground: "hsl(var(--primary-foreground))",
        },
        secondary: {
          DEFAULT: "hsl(var(--secondary))",
          foreground: "hsl(var(--secondary-foreground))",
        },
        // ... 50+ more lines
      },
      borderRadius: {
        lg: "var(--radius)",
        md: "calc(var(--radius) - 2px)",
        sm: "calc(var(--radius) - 4px)",
      },
      keyframes: {
        "accordion-down": {
          from: { height: "0" },
          to: { height: "var(--radix-accordion-content-height)" },
        },
        "accordion-up": {
          from: { height: "var(--radix-accordion-content-height)" },
          to: { height: "0" },
        },
      },
      animation: {
        "accordion-down": "accordion-down 0.2s ease-out",
        "accordion-up": "accordion-up 0.2s ease-out",
      },
    },
  },
  plugins: [require("tailwindcss-animate"), require("@tailwindcss/typography")],
}
```

**Total:** 100+ lines of JavaScript configuration

### Tailwind v4: CSS-First Configuration

```css
/* globals.css (v4) */
@import "tailwindcss";
@import "@repo/design-system/theme.css";
@import "@repo/design-system/custom-styles.css";

@plugin "tailwindcss-animate";
@plugin "@tailwindcss/typography";

@custom-variant dark (&:is(.dark, .dark *));
```

**Total:** 10 lines of CSS

**Reduction:** 90% fewer lines for core configuration

## Why CSS-First Is Better (Technical Deep Dive)

### 1. Single Source of Truth

**v3 problem:** Configuration split across two files

```javascript
// tailwind.config.js
theme: {
  extend: {
    colors: {
      primary: "hsl(var(--primary))"
    }
  }
}
```

```css
/* globals.css */
:root {
  --primary: 220 90% 56%;
}
```

**Result:** Have to jump between files to understand theming.

**v4 solution:** Everything in CSS

```css
/* theme.css */
:root {
  --primary: 220 90% 56%;
}

/* Utilities generated automatically from CSS variables */
/* No config file needed! */
```

**Benefit:** See the entire theming system in one place.

### 2. Better Developer Experience

**v3:** Change theme → restart dev server → wait 10-20 seconds

```bash
# Every config change:
1. Edit tailwind.config.js
2. Ctrl+C (stop dev server)
3. yarn dev (restart)
4. Wait for rebuild
5. Refresh browser
```

**v4:** Change theme → instant hot reload (0.5 seconds)

```bash
# Every CSS change:
1. Edit theme.css
2. See update immediately (HMR)
# No restart needed!
```

**Time saved:** ~3 hours/quarter (assuming 30 config tweaks)

### 3. Native CSS Features

**v4 embraces modern CSS:**

```css
/* Custom variants using native CSS */
@custom-variant dark (&:is(.dark, .dark *));

/* Equivalent to v3's complex darkMode config */
/* But more powerful - supports any selector */
```

**You can now:**

```css
/* Target specific parent combinations */
@custom-variant sidebar (&:is(.sidebar, .sidebar *));

/* Create print styles */
@custom-variant print (@media print);

/* Add high contrast mode */
@custom-variant high-contrast (@media (prefers-contrast: high));
```

**v3 equivalent:** Would require complex plugin or config objects

### 4. Cleaner Plugin System

**v3 plugins:**

```javascript
// tailwind.config.js
plugins: [
  require("tailwindcss-animate"),
  require("@tailwindcss/typography"),
  require("@tailwindcss/forms"),
  require("@tailwindcss/aspect-ratio"),
]
```

**v4 plugins:**

```css
/* globals.css */
@plugin "tailwindcss-animate";
@plugin "@tailwindcss/typography";
@plugin "@tailwindcss/forms";
@plugin "@tailwindcss/aspect-ratio";
```

**Why better:**

- Visual clarity (see all plugins in one glance)
- Order matters (CSS cascade rules apply)
- No require() statements
- Works with CSS imports naturally

## The Migration Process (Step-by-Step)

### Step 1: Backup Your Current Configuration

```bash
# Create backup branch
git checkout -b backup-before-tailwind-v4

# Commit current state
git add .
git commit -m "Backup before Tailwind v4 migration"

# Create new migration branch
git checkout -b feat/tailwind-v4-migration
```

### Step 2: Update Dependencies

```bash
# Update to Tailwind v4
npm install tailwindcss@next @tailwindcss/postcss@next

# Or with yarn
yarn add tailwindcss@next @tailwindcss/postcss@next

# Update plugins to v4-compatible versions
npm install @tailwindcss/typography@latest tailwindcss-animate@latest
```

**Check your package.json:**

```json
{
  "dependencies": {
    "tailwindcss": "^4.0.0-beta.1",
    "@tailwindcss/postcss": "^4.0.0-beta.1",
    "@tailwindcss/typography": "^0.6.0",
    "tailwindcss-animate": "^1.0.7"
  }
}
```

### Step 3: Update PostCSS Configuration

**Before (v3):**

```javascript
// postcss.config.js
module.exports = {
  plugins: {
    tailwindcss: {},
    autoprefixer: {},
  },
}
```

**After (v4):**

```javascript
// postcss.config.js
module.exports = {
  plugins: {
    "@tailwindcss/postcss": {},
  },
}
```

**Key change:** `tailwindcss` → `@tailwindcss/postcss`

**Note:** Autoprefixer is now built-in! No separate plugin needed.

### Step 4: Convert Configuration to CSS

**Extract your v3 config sections:**

1. **Theme colors** → CSS variables in `theme.css`
2. **Plugins** → `@plugin` directives in `globals.css`
3. **Dark mode** → `@custom-variant` in `globals.css`
4. **Custom utilities** → CSS classes in `custom-styles.css`

**Example conversion:**

**v3 colors:**

```javascript
// tailwind.config.js
theme: {
  extend: {
    colors: {
      primary: {
        DEFAULT: "hsl(var(--primary))",
        foreground: "hsl(var(--primary-foreground))",
      },
      secondary: {
        DEFAULT: "hsl(var(--secondary))",
        foreground: "hsl(var(--secondary-foreground))",
      },
    },
  },
}
```

**v4 equivalent:**

```css
/* theme.css */
:root {
  --primary: 220 90% 56%;
  --primary-foreground: 0 0% 100%;
  --secondary: 240 4.8% 95.9%;
  --secondary-foreground: 240 5.9% 10%;
}

/* Utilities auto-generated:
   - bg-primary → background: hsl(var(--primary))
   - text-primary-foreground → color: hsl(var(--primary-foreground))
   - etc.
*/
```

### Step 5: Update globals.css

**v3 structure:**

```css
/* globals.css */
@tailwind base;
@tailwind components;
@tailwind utilities;

@layer base {
  /* Custom base styles */
}
```

**v4 structure:**

```css
/* globals.css */
@import "tailwindcss";
@import "@repo/design-system/theme.css";
@import "@repo/design-system/custom-styles.css";

@plugin "tailwindcss-animate";
@plugin "@tailwindcss/typography";

@custom-variant dark (&:is(.dark, .dark *));
```

**Key changes:**

- `@tailwind` directives → `@import "tailwindcss"`
- Plugins moved to CSS
- Dark mode configured with `@custom-variant`

### Step 6: Delete Old Configuration

```bash
# Remove v3 config file
rm tailwind.config.js

# Or if you have TypeScript config
rm tailwind.config.ts
```

**Important:** v3 and v4 configs conflict. Must delete the old one!

### Step 7: Test Your Build

```bash
# Development
npm run dev
# or
yarn dev

# Production build
npm run build
# or
yarn build
```

**What to check:**

- ✅ No build errors
- ✅ Styles load correctly
- ✅ Dark mode works (if you use it)
- ✅ Custom colors apply
- ✅ Plugin utilities available (prose, animate, etc.)

## What Broke (And How to Fix It)

### Issue 1: Content Paths Not Detected

**Problem:** Tailwind v4 doesn't use `content` array in config anymore.

**v3 way:**

```javascript
// tailwind.config.js
content: ["./src/**/*.{js,ts,jsx,tsx}"]
```

**v4 solution:** Automatic content detection!

Tailwind v4 scans your project automatically. If you need explicit paths:

```css
/* globals.css */
@import "tailwindcss" source("./src/**/*.{js,ts,jsx,tsx}");
```

**But:** In my testing, auto-detection worked perfectly. No explicit paths needed.

### Issue 2: Custom Plugin Not Working

**Problem:** Custom JavaScript plugin from v3 doesn't work in v4.

**v3 plugin:**

```javascript
// tailwind.config.js
plugins: [
  function ({ addUtilities }) {
    addUtilities({
      ".scrollbar-hide": {
        "-ms-overflow-style": "none",
        "scrollbar-width": "none",
        "&::-webkit-scrollbar": {
          display: "none",
        },
      },
    })
  },
]
```

**v4 solution:** Convert to pure CSS

```css
/* custom-styles.css */
@layer utilities {
  .scrollbar-hide {
    -ms-overflow-style: none;
    scrollbar-width: none;
  }

  .scrollbar-hide::-webkit-scrollbar {
    display: none;
  }
}
```

**Import in globals.css:**

```css
@import "tailwindcss";
@import "./custom-styles.css";
```

### Issue 3: Container Queries Not Working

**Problem:** Container queries require explicit plugin in v4.

**v3:** Automatic container support

**v4 fix:**

```css
/* globals.css */
@import "tailwindcss";
@plugin "@tailwindcss/container-queries";
```

Or install if not available:

```bash
npm install @tailwindcss/container-queries
```

### Issue 4: Dark Mode Selector Changed

**Problem:** Dark mode uses `.dark` class but not detecting.

**v3 config:**

```javascript
darkMode: ["class"]
```

**v4 equivalent:**

```css
@custom-variant dark (&:is(.dark, .dark *));
```

**Explanation:** `&:is(.dark, .dark *)` matches:

- Elements with `.dark` class directly
- Elements inside `.dark` parent

## Performance Improvements

### Build Speed

**Metrics from my migration:**

| Metric           | v3    | v4   | Improvement |
| ---------------- | ----- | ---- | ----------- |
| Cold build       | 12.3s | 8.7s | 29% faster  |
| Hot reload       | 1.2s  | 0.4s | 67% faster  |
| Config change    | 18s   | 0.5s | 97% faster  |
| Production build | 45s   | 38s  | 16% faster  |

**Why faster:**

- No JavaScript config parsing
- Native CSS processing
- Optimized PostCSS plugin
- Better caching

### Bundle Size

**CSS output comparison:**

| Build             | v3     | v4     | Difference  |
| ----------------- | ------ | ------ | ----------- |
| Development       | 8.2 MB | 6.1 MB | 26% smaller |
| Production (gzip) | 12 KB  | 11 KB  | 8% smaller  |

**Note:** Production size similar because Tailwind v3 was already well-optimized. The big win is development speed.

## Migration Checklist

**Pre-Migration:**

- [ ] Back up project (create git branch)
- [ ] Document current Tailwind config
- [ ] Test suite passing
- [ ] Note any custom plugins

**Migration Steps:**

- [ ] Update dependencies (`tailwindcss@next`, `@tailwindcss/postcss@next`)
- [ ] Update PostCSS config (`@tailwindcss/postcss`)
- [ ] Convert theme to CSS variables (`theme.css`)
- [ ] Move plugins to `@plugin` directives (`globals.css`)
- [ ] Convert custom utilities to CSS (`custom-styles.css`)
- [ ] Add dark mode variant if needed (`@custom-variant`)
- [ ] Delete `tailwind.config.js`
- [ ] Test dev build (`npm run dev`)
- [ ] Test production build (`npm run build`)

**Post-Migration Verification:**

- [ ] All pages render correctly
- [ ] Dark mode works (if applicable)
- [ ] Custom colors apply
- [ ] Typography plugin working (`prose` classes)
- [ ] Animation plugin working
- [ ] No console errors
- [ ] Hot reload fast (<1 second)

## Should You Migrate?

### ✅ Migrate if:

- You're starting a new project
- You frequently tweak theme/config
- You want faster development
- You prefer CSS-first tools
- You have time for thorough testing

### ⏸️ Wait if:

- You have complex custom plugins (may need rewriting)
- You're on tight deadlines
- You depend on v3-specific features
- Your team isn't familiar with modern CSS

### ❌ Don't migrate if:

- You're happy with v3 and don't need v4 features
- You have heavily customized build process
- You use unsupported plugins that aren't updated

**Personal recommendation:** Migrate. The CSS-first approach is the future, and the DX improvements are substantial.

## Common Gotchas

❌ **Keeping `tailwind.config.js`**

- v3 and v4 configs conflict
- Always delete the old config file

❌ **Forgetting to update PostCSS**

- Must use `@tailwindcss/postcss`, not `tailwindcss`

❌ **Not restarting dev server after PostCSS change**

- PostCSS changes require restart (one time only)

❌ **Converting complex plugins incorrectly**

- Some JavaScript plugins can't be pure CSS
- May need to keep as custom PostCSS plugin

❌ **Not testing dark mode**

- Dark mode selector changed
- Test all theme variants after migration
