## What Is Atomic Architecture?

**Atomic architecture** is a design pattern that orders component fields from foundational (atomic) to complex (compound).

**The pattern:** Background → Badge → Header → Component Content

**Why this order?**

1. **Background** (most foundational): Sets the visual foundation
2. **Badge** (small accent): Optional eyebrow label
3. **Header** (orientation): Title, description, heading size
4. **Component Content** (specific): Lists, grids, buttons, etc.

**Analogy:** Building a house

- Background = Foundation (you start here)
- Badge = Decorative trim
- Header = Room labels/signs
- Content = Furniture and fixtures

## Before: Inconsistent Field Ordering

### FeatureGridSection (Before)

```json
{
  "layouts": {
    "edit": [
      "items",
      "listItems",
      "footerNote",
      "gridColumns",

      "badge", // ← Should be SECOND
      "header" // ← Should be THIRD
    ]
  }

```

**User experience:**

- Start editing → see "items" first (content-specific)
- Want to change background? Scroll down
- Looking for header settings? Keep scrolling
- No predictable location

### RoadmapSection (Before)

```json

      "roadmapItems", // Content first
      "footerNotes",
      "background", // ← Should be at top
      "badge",
      "header"
    ]
  }
}
```

**Problem:** Different order than FeatureGridSection!

- FeatureGridSection: content → background → badge → header
- RoadmapSection: content → background → badge → header
- Both wrong, but also inconsistent with each other

### FinalCTASection (Before)

```json
{
  "layouts": {
    "edit": [
      "ctaButtons", // Content first (again!)
      "background",
      "badge",
      "header"
    ]
  }
}
```

**Result:** 3 sections, 3 different patterns. Chaos.

## After: Atomic Architecture Pattern

### All Sections (After)

```json
{
  "layouts": {
    "edit": [
      "background", // 1. Foundation
      "badge", // 2. Accent
      "header", // 3. Orientation
      "items", // 4. Component-specific content
      "listItems",
      "footerNote",
      "gridColumns"
    ]
  }
}
```

**User experience:**

- Start editing → see background first (foundation)
- Badge settings → next (small accent)
- Header settings → third (title, description)
- Content fields → last (varies by component)

**Consistency:** ALL 8 landing page sections follow this pattern

## How to Implement in Strapi

### Step 1: Locate Config Sync Files

Strapi stores component configurations in:

```
apps/strapi/config/sync/
  core-store.plugin_content_manager_configuration_components##sections.*.json
```

**Files to update:**

```
feature-grid-section.json
roadmap-section.json
final-cta-section.json
workflow-section.json
newsletter-cta-section.json
benefits-section.json
metrics-section.json
partner-showcase-section.json
```

### Step 2: Edit the Layout Array

**Example: FeatureGridSection**

File: `config/sync/core-store.plugin_content_manager_configuration_components##sections.feature-grid-section.json`

**Before:**

```json
{
  "uid": "sections.feature-grid-section",
  "settings": {
    "bulkable": true,
    "filterable": true,
    "searchable": true,
    "pageSize": 10,
    "mainField": "id",
    "defaultSortBy": "id",
    "defaultSortOrder": "ASC"
  },
  "metadatas": {
    "background": {
      "edit": {
        "label": "background",
        "description": "",
        "placeholder": "",
        "visible": true,
        "editable": true
      }
    }
    // ... other metadata
  },
  "layouts": {
    "list": ["id"],
    "edit": [
      "items", // ← Wrong order
      "listItems",
      "footerNote",
      "gridColumns",
      "background",
      "badge",
      "header"
    ]
  }
}
```

**After:**

```json
{
  "uid": "sections.feature-grid-section",
  "settings": {
    "bulkable": true,
    "filterable": true,
    "searchable": true,
    "pageSize": 10,
    "mainField": "id",
    "defaultSortBy": "id",
    "defaultSortOrder": "ASC"
  },
  "metadatas": {
    // ... unchanged
  },
  "layouts": {
    "list": ["id"],
    "edit": [
      "background", // 1. Foundation
      "badge", // 2. Accent
      "header", // 3. Orientation
      "items", // 4. Content (component-specific)
      "listItems",
      "footerNote",
      "gridColumns"
    ]
  }
}
```

**Key change:** Only the `layouts.edit` array order changes. Everything else stays the same.

### Step 3: Import Config Sync

```bash
# Start Strapi
cd apps/strapi
yarn dev

# Navigate to Config Sync
open http://localhost:1337/admin/settings/config-sync
```

**In Strapi Admin:**

1. Click **"Import"** button (Database ← Files direction)
2. Review changes in diff view
3. Click **"Import"** to apply

**What this does:**

- Reads JSON files from `config/sync/`
- Compares with current database
- Shows diff of changes
- Updates database on confirmation

**Expected result:**

```
✅ Imported 8 component configurations
✅ Field ordering updated for all sections
```

### Step 4: Verify in Content-Type Builder

Navigate to: Content-Type Builder → Components → sections → feature-grid-section

**Verify field order:**

1. background ✅
2. badge ✅
3. header ✅
4. items ✅
5. listItems ✅
6. footerNote ✅
7. gridColumns ✅

**Repeat for all sections.**

## Pattern Variations by Component Type

### Standard Section (Most Common)

**Order:** Background → Badge → Header → Content Fields

**Example: FeatureGridSection**

```json
{
  "layouts": {
    "edit": [
      "background",
      "badge",
      "header",
      "items", // Main content
      "listItems", // Secondary content
      "footerNote", // Tertiary content
      "gridColumns" // Layout option
    ]
  }
}
```

### CTA Section (Action-Focused)

**Order:** Background → Badge → Header → Buttons

**Example: FinalCTASection**

```json
{
  "layouts": {
    "edit": [
      "background",
      "badge",
      "header",
      "ctaButtons" // Action buttons
    ]
  }
}
```

### Metrics Section (Data Display)

**Order:** Background → Badge → Header → Data → Layout

**Example: MetricsSection**

```json
{
  "layouts": {
    "edit": [
      "background",
      "badge",
      "header",
      "metrics", // Data points
      "gridColumns" // Layout control
    ]
  }
}
```

### Newsletter Section (Form)

**Order:** Background → Badge → Header → Form Fields

**Example: NewsletterCTASection**

```json
{
  "layouts": {
    "edit": [
      "background",
      "badge",
      "header",
      "heading", // Form heading
      "description",
      "inputPlaceholder",
      "buttonText",
      "gdprLabel",
      "gdprLink",
      "benefits"
    ]
  }
}
```

**Universal principle:** Foundation → Accent → Orientation → Content (specifics vary)

## Common Pitfalls

### ❌ Changing Field Names

```json
{
  "layouts": {
    "edit": [
      "bg", // ← Wrong! Field name must match schema
      "badge",
      "header"
    ]
  }
}
```

**Fix:** Only reorder, never rename. Field names must match the component schema.

### ❌ Forgetting to Import Config Sync

```bash
# You edited JSON files but didn't import
# Result: Strapi admin still shows old order
```

**Fix:** Always import config sync after editing JSON files.

### ❌ Not Testing All Sections

```bash
# You updated FeatureGridSection but forgot RoadmapSection
# Result: Inconsistent experience
```

**Fix:** Update ALL sections to follow the pattern (batch refactor).

### ❌ Applying Pattern to Non-Section Components

```json
// StatCard molecule
{
  "layouts": {
    "edit": [
      "background", // ← StatCard doesn't have background!
      "number",
      "label",
      "description"
    ]
  }
}
```

**Fix:** Atomic architecture applies to **sections**, not molecules/atoms. For smaller components, order by: data → display → styling.

## Extending the Pattern

### Adding New Sections

When creating new sections, follow the pattern:

```json
{
  "layouts": {
    "edit": [
      "background", // Always first
      "badge", // Always second (if present)
      "header" // Always third (if present)
      // ... component-specific fields below
    ]
  }
}
```

### Multi-Language Considerations

If using Strapi i18n:

```json
{
  "layouts": {
    "edit": [
      "background", // Not translated (layout)
      "badge", // Not translated (layout)
      "header", // Not translated (layout)
      "heading", // ← Translated field
      "description", // ← Translated field
      "items" // ← Translated field (repeatable)
    ]
  }
}
```

**Pattern still applies:** Foundation → Accent → Orientation → Translated Content
