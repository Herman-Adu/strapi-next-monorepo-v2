# Tutorial: Building Environment-Specific Database Seeding

**Difficulty:** 🟡 Intermediate  
**Time to Complete:** 30 minutes  
**Platform:** Cross-platform (bash scripts + Node.js)

**What You'll Learn:**

- Why the same seed script can't work for both CI and development
- How to design two-script system (destructive CI, safe dev)
- How to implement environment detection
- How to organize package.json scripts with clear naming
- How to prevent accidental data loss with explicit safety warnings

**Prerequisites:**

- Understanding of bash scripting basics
- Node.js and npm/yarn knowledge
- Familiarity with CI/CD concepts
- Experience with Strapi or similar CMS (helpful but not required)

**Problem Statement:**

You have a seed script that works perfectly in CI (Continuous Integration). It:

1. Drops the database schema: `DROP SCHEMA IF EXISTS public CASCADE`
2. Recreates schema from scratch
3. Seeds test data

This is **perfect for CI** (fresh environment every time), but **catastrophic for local development** (destroys your real content).

**The real incident:** December 2, 2025 - ran CI seed script in development database:

```bash
yarn seed:e2e  # Oops! This was the CI version
# Result: 203 entities + 331 assets deleted in 2 seconds
```

**This tutorial teaches you how to prevent this from ever happening.**

---

## Step 1: Understand the Core Problem

### Why One Script Can't Serve Both Environments

| Requirement              | CI Environment        | Development Environment |
| ------------------------ | --------------------- | ----------------------- |
| **Starting State**       | Empty database        | Existing content        |
| **Desired Outcome**      | Clean slate every run | Preserve existing data  |
| **Data Persistence**     | Temporary (per run)   | Permanent (across runs) |
| **Risk of Data Loss**    | Zero (no real data)   | High (real work)        |
| **Destructive Commands** | ✅ Safe to use        | ❌ Catastrophic         |
| **Performance**          | Speed matters         | Reliability matters     |

**The fundamental conflict:**

- CI **requires** destructive operations (`DROP SCHEMA CASCADE`)
- Development **forbids** destructive operations (would lose real work)

**Solution:** Two separate scripts with explicit naming.

---

## Step 2: Design the Two-Script System

### Architecture Overview

```
Seed Scripts System
├── seed-e2e-data.sh           # CI ONLY - Destructive
│   ├── DROP SCHEMA CASCADE    # Wipes everything
│   └── Create from scratch
│
└── seed-e2e-data-safe.sh      # DEV ONLY - Non-Destructive
    ├── Check if exists
    └── Update vs create
```

**Naming convention:**

- Base name: `seed-e2e-data.sh` (original CI script)
- Safe variant: `seed-e2e-data-safe.sh` (add `-safe` suffix)

**Why not automatic detection?**

- ❌ Environment variables can be wrong
- ❌ Easy to accidentally run wrong script
- ✅ Explicit is better than implicit (developer chooses intentionally)

## Step 3: Create the Destructive CI Script

### File: `apps/strapi/scripts/seed-e2e-data.sh`

```bash
#!/bin/bash

# ==============================================================================
# DESTRUCTIVE E2E Test Data Seeding Script (CI USE ONLY)
# ==============================================================================
#
# ⚠️  WARNING: THIS SCRIPT DELETES ALL DATABASE CONTENT ⚠️
#
# Purpose: Creates clean E2E test environment from scratch
#
# Usage:
#   - CI: yarn seed:e2e (GitHub Actions, GitLab CI, etc.)
#   - Local: NEVER USE THIS IN DEVELOPMENT! Use seed:e2e:safe instead
#
# What This Does:
#   1. Drops entire database schema (DELETE ALL DATA)
#   2. Recreates schema from scratch
#   3. Seeds E2E test data
#
# ==============================================================================

set -e  # Exit on error

# Colors for output
RED='\033[0;31m'
GREEN='\033[0;32m'
YELLOW='\033[1;33m'
BLUE='\033[0;34m'
NC='\033[0m' # No Color

echo -e "${RED}⚠️  DESTRUCTIVE E2E Test Data Seeding (CI ONLY)${NC}"
echo -e "${RED}=======================================${NC}"
echo -e "${RED}This will DELETE ALL database content!${NC}"
echo ""

# ------------------------------------------------------------------------------
# 1. VERIFY WE'RE IN CI ENVIRONMENT (Optional Safety Check)
# ------------------------------------------------------------------------------

if [ -z "$CI" ] && [ -z "$GITHUB_ACTIONS" ]; then
  echo -e "${YELLOW}⚠️  Warning: Not in CI environment${NC}"
  echo -e "${YELLOW}Are you SURE you want to run the destructive script?${NC}"
  echo -e "${YELLOW}Use seed:e2e:safe for local development instead.${NC}"
  echo ""
  read -p "Type 'DELETE ALL DATA' to confirm: " confirmation

  if [ "$confirmation" != "DELETE ALL DATA" ]; then
    echo -e "${RED}❌ Aborted - use seed:e2e:safe for safe seeding${NC}"
    exit 1
  fi
fi

# ------------------------------------------------------------------------------
# 2. LOAD DATABASE CONNECTION
# ------------------------------------------------------------------------------

echo -e "${YELLOW}📊 Loading database connection...${NC}"

# Change to script directory, then go to strapi root
SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
cd "$SCRIPT_DIR/.."

# Load .env file if it exists
if [ -f ".env" ]; then
  export $(grep -v '^#' .env | grep DATABASE_URL | xargs)
fi

if [ -z "$DATABASE_URL" ]; then
  echo -e "${RED}❌ ERROR: DATABASE_URL not set${NC}"
  exit 1
fi

# Extract database connection details from DATABASE_URL
# Format: postgresql://user:password@host:port/dbname
DB_NAME=$(echo "$DATABASE_URL" | sed -n 's/.*\/\([^?]*\).*/\1/p')
DB_USER=$(echo "$DATABASE_URL" | sed -n 's/.*:\/\/\([^:]*\).*/\1/p')
DB_HOST=$(echo "$DATABASE_URL" | sed -n 's/.*@\([^:]*\).*/\1/p')

echo -e "${GREEN}✅ Database: $DB_NAME${NC}"

# ------------------------------------------------------------------------------
# 3. DROP AND RECREATE SCHEMA (DESTRUCTIVE!)
# ------------------------------------------------------------------------------

echo -e "${RED}🗑️  Dropping database schema...${NC}"

psql "$DATABASE_URL" -c "DROP SCHEMA IF EXISTS public CASCADE;"
psql "$DATABASE_URL" -c "CREATE SCHEMA public;"
psql "$DATABASE_URL" -c "GRANT ALL ON SCHEMA public TO $DB_USER;"

echo -e "${GREEN}✅ Schema recreated (all data deleted)${NC}"

# ------------------------------------------------------------------------------
# 4. SEED E2E TEST DATA
# ------------------------------------------------------------------------------

echo -e "${YELLOW}🌱 Seeding E2E test data...${NC}"

node scripts/run-seed.js

if [ $? -eq 0 ]; then
  echo -e "${GREEN}✅ E2E test data seeded successfully${NC}"
else
  echo -e "${RED}❌ E2E seeding failed${NC}"
  exit 1
fi

# ------------------------------------------------------------------------------
# 5. COMPLETION
# ------------------------------------------------------------------------------

echo ""
echo -e "${GREEN}=========================================${NC}"
echo -e "${GREEN}🎉 E2E Test Environment Ready!${NC}"
echo -e "${GREEN}=========================================${NC}"
echo -e "✅ Database: Clean slate"
echo -e "✅ E2E test page: Created"
echo -e "✅ Ready for CI testing"
echo ""
```

**Key features:**

- ✅ Clear warning in header and output
- ✅ CI environment detection (optional safety)
- ✅ Manual confirmation required if not in CI
- ✅ Colored output for visibility
- ✅ Clear success/failure messages

## Step 4: Create the Safe Development Script

### File: `apps/strapi/scripts/seed-e2e-data-safe.sh`

```bash
#!/bin/bash

# ==============================================================================
# SAFE E2E Test Data Seeding Script (Non-Destructive)
# ==============================================================================
#
# Purpose: Creates ONLY the E2E test page WITHOUT deleting existing content
#
# Usage:
#   - Local: yarn seed:e2e:safe (from apps/strapi directory)
#   - CI: Use the destructive script (seed-e2e-data.sh)
#
# Safety Features:
#   - Does NOT drop database schema
#   - Does NOT reset existing content
#   - Only creates/updates the E2E test page
#   - Preserves all existing pages, media, navbar, footer
#
# ==============================================================================

set -e  # Exit on error

# Colors for output
RED='\033[0;31m'
GREEN='\033[0;32m'
YELLOW='\033[1;33m'
BLUE='\033[0;34m'
NC='\033[0m' # No Color

echo -e "${GREEN}🌱 SAFE E2E Test Data Seeding (Non-Destructive)${NC}"
echo "========================================"

# ------------------------------------------------------------------------------
# 1. LOAD DATABASE CONNECTION
# ------------------------------------------------------------------------------

echo -e "${YELLOW}📊 Checking database connection...${NC}"

# Change to script directory, then go to strapi root
SCRIPT_DIR="$(cd "$(dirname "${BASH_SOURCE[0]}")" && pwd)"
cd "$SCRIPT_DIR/.."

# Load .env file if it exists
if [ -f ".env" ]; then
  export $(grep -v '^#' .env | grep DATABASE_URL | xargs)
fi

if [ -z "$DATABASE_URL" ]; then
  echo -e "${RED}❌ ERROR: DATABASE_URL not set${NC}"
  exit 1
fi

DB_NAME=$(echo "$DATABASE_URL" | sed -n 's/.*\/\([^?]*\).*/\1/p')
echo -e "${GREEN}✅ Connected to database: $DB_NAME${NC}"

# ------------------------------------------------------------------------------
# 2. VERIFY STRAPI BUILD
# ------------------------------------------------------------------------------

echo -e "${YELLOW}🔍 Verifying Strapi build...${NC}"

if [ ! -d ".strapi" ]; then
  echo -e "${RED}❌ Strapi not built yet. Run 'yarn build' first.${NC}"
  exit 1
fi

echo -e "${GREEN}✅ Strapi build verified${NC}"

# ------------------------------------------------------------------------------
# 3. SAFETY CONFIRMATION
# ------------------------------------------------------------------------------

echo -e "${GREEN}✅ This script will NOT delete existing content${NC}"
echo -e "${BLUE}ℹ️  It will only create/update the E2E test page${NC}"
echo ""

# ------------------------------------------------------------------------------
# 4. SEED E2E TEST DATA (Non-Destructive)
# ------------------------------------------------------------------------------

echo -e "${YELLOW}🌱 Creating/updating E2E test page...${NC}"

node scripts/run-seed-safe.js

if [ $? -eq 0 ]; then
  echo -e "${GREEN}✅ E2E test page created/updated successfully${NC}"
else
  echo -e "${RED}❌ E2E page creation failed${NC}"
  exit 1
fi

# ------------------------------------------------------------------------------
# 5. COMPLETION
# ------------------------------------------------------------------------------

echo ""
echo -e "${GREEN}=========================================${NC}"
echo -e "${GREEN}🎉 Safe E2E Seeding Complete!${NC}"
echo -e "${GREEN}=========================================${NC}"
echo -e "✅ E2E test page: Created/Updated"
echo -e "✅ Existing content: Preserved"
echo -e "✅ Ready for local E2E testing"
echo ""
```

**Key differences from CI script:**

- ❌ No `DROP SCHEMA CASCADE`
- ✅ Green header (safe operation)
- ✅ Calls `run-seed-safe.js` (idempotent version)
- ✅ Clear messaging about preservation

## Step 5: Create Idempotent Seed Logic

### File: `apps/strapi/database/seeds/e2e-test-data-safe.ts`

```typescript
/**
 * SAFE E2E Test Data Seeding Script (Non-Destructive)
 *
 * Creates ONLY the E2E test page WITHOUT deleting existing content
 *
 * Safety Features:
 * - Checks if E2E test page already exists
 * - Updates existing page instead of creating duplicate
 * - Does NOT touch other pages, media, or content
 */

export default async ({ strapi }: { strapi: any }) => {
  console.log("🌱 Starting SAFE E2E test data seeding (non-destructive)...")

  try {
    // ====================================================================
    // 1. CHECK IF E2E TEST PAGE EXISTS
    // ====================================================================

    console.log("🔍 Checking for existing E2E test page...")

    const existingPages = await strapi.documents("api::page.page").findMany({
      filters: {
        slug: { $eq: "e2e-test-page" },
        locale: { $eq: "en" },
      },
      locale: "en",
    })

    let e2eTestPage

    // ====================================================================
    // 2. UPDATE vs CREATE
    // ====================================================================

    if (existingPages && existingPages.length > 0) {
      // Page exists - UPDATE it
      console.log("✅ E2E test page already exists - updating...")

      e2eTestPage = await strapi.documents("api::page.page").update({
        documentId: existingPages[0].documentId,
        data: getE2EPageData(),
        locale: "en",
      })

      console.log(`✅ Updated E2E test page (ID: ${e2eTestPage.documentId})`)
    } else {
      // Page doesn't exist - CREATE it
      console.log("📄 Creating new E2E test page...")

      e2eTestPage = await strapi.documents("api::page.page").create({
        data: getE2EPageData(),
        locale: "en",
      })

      console.log(`✅ Created E2E test page (ID: ${e2eTestPage.documentId})`)
    }

    // ====================================================================
    // 3. PUBLISH THE PAGE
    // ====================================================================

    console.log("📤 Publishing E2E test page...")

    await strapi.documents("api::page.page").publish({
      documentId: e2eTestPage.documentId,
      locale: "en",
    })

    console.log("✅ E2E test page published successfully")

    // ====================================================================
    // 4. SUMMARY
    // ====================================================================

    console.log("\n" + "=".repeat(60))
    console.log("🎉 Safe E2E Test Data Seeding Complete!")
    console.log("=".repeat(60))
    console.log(`✅ E2E test page: /en/e2e-test-page`)
    console.log(`✅ All existing content preserved`)
    console.log(`✅ Ready for E2E testing`)
    console.log("=".repeat(60) + "\n")
  } catch (error: any) {
    console.error("❌ Error during safe E2E seeding:")
    console.error(error)
    throw error
  }
}

/**
 * Returns the E2E page data structure
 * This would include your actual page content
 */
function getE2EPageData() {
  return {
    title: "E2E Test Page",
    slug: "e2e-test-page",
    fullPath: "/e2e-test-page",

    seo: {
      metaTitle: "E2E Test Page",
      metaDescription: "Test page for end-to-end testing",
      preventIndexing: true,
    },

    content: [
      {
        __component: "sections.newsletter-cta-section",
        heading: "Subscribe to Our Newsletter",
        description: "Get updates delivered to your inbox",
        inputPlaceholder: "your.email@example.com",
        buttonText: "Subscribe",
        gdprLabel: "I agree to receive marketing emails",
        // ... full component data
      },
      // ... more sections
    ],
  }
}
```

**Key pattern (idempotent):**

```typescript
// STEP 1: Check if exists
const existing = await strapi.documents("api::page.page").findMany({
  filters: { slug: "e2e-test-page" },
})

// STEP 2: Update vs create
if (existing.length > 0) {
  await strapi.documents("api::page.page").update({
    /* update existing */
  })
} else {
  await strapi.documents("api::page.page").create({
    /* create new */
  })
}
```

## Step 6: Organize package.json Scripts

### File: `apps/strapi/package.json`

```json
{
  "name": "@repo/strapi",
  "scripts": {
    "dev": "strapi develop",
    "build": "strapi build",

    "seed:e2e": "bash scripts/seed-e2e-data.sh",
    "seed:e2e:safe": "bash scripts/seed-e2e-data-safe.sh"
  }
}
```

**Root package.json (for easier access):**

```json
{
  "name": "monorepo",
  "scripts": {
    "strapi:seed": "yarn workspace @repo/strapi seed:e2e:safe",
    "strapi:seed:ci": "yarn workspace @repo/strapi seed:e2e"
  }
}
```

**Usage:**

```bash
# From apps/strapi directory
yarn seed:e2e:safe     # Development (safe)
yarn seed:e2e          # CI only (destructive)

# From root directory
yarn strapi:seed       # Development (safe)
yarn strapi:seed:ci    # CI only (destructive)
```

**Inline warnings (optional but recommended):**

```json
{
  "scripts": {
    "seed:e2e": "echo '⚠️  WARNING: This will DELETE ALL DATA! Use seed:e2e:safe for local dev.' && bash scripts/seed-e2e-data.sh",
    "seed:e2e:safe": "bash scripts/seed-e2e-data-safe.sh"
  }
}
```

## Key Takeaways

✅ **One script can't safely serve both CI and development**  
✅ **Explicit naming beats environment detection** (seed:e2e vs seed:e2e:safe)  
✅ **Idempotent patterns prevent duplicate data** (check-then-update)  
✅ **Clear warnings prevent accidents** (red text, confirmation prompts)  
✅ **CI should use destructive scripts** (fresh environment = clean slate)  
✅ **Development should use safe scripts** (preserve existing work)

**Common Pitfalls:**

- ❌ Trying to make one script work for both environments
- ❌ Using environment variables for detection (easy to misconfigure)
- ❌ Not testing safe script (might still have destructive commands)
- ❌ Forgetting to update CI workflow after creating new scripts
