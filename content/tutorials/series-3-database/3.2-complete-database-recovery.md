## Step 1: Understanding Strapi Export Format

Before recovering, understand what you're working with.

### Strapi Export vs pg_dump

| Feature                | Strapi Export                             | pg_dump                             |
| ---------------------- | ----------------------------------------- | ----------------------------------- |
| **Format**             | JSONL (human-readable)                    | SQL dump (raw database)             |
| **Portability**        | ✅ Cross-database (Postgres/MySQL/SQLite) | ❌ Database-specific                |
| **Size**               | Larger (~30 MB for 200 entities)          | Smaller (~5 MB)                     |
| **Content Only**       | ✅ Yes (schemas + entities + media)       | ❌ No (includes indexes, sequences) |
| **Version Compatible** | ✅ Works across Strapi versions           | ⚠️ PostgreSQL version-dependent     |
| **Media Files**        | ✅ Included in export                     | ❌ Separate backup needed           |
| **Relationships**      | ✅ Preserved automatically                | ⚠️ Must restore in correct order    |
| **Local Development**  | ✅ Perfect                                | ⚠️ Overkill                         |
| **Production Backup**  | ⚠️ Good for content                       | ✅ Better for full system           |

**Recommendation:**

- **Use Strapi export for:** Content backups, development, migrations, version upgrades
- **Use pg_dump for:** Production full-system backups, infrastructure disaster recovery

## Step 2: Create a Backup (Before You Need It)

### Manual Export (One-Time Backup)

```bash
cd apps/strapi

# Export everything (schemas + entities + media)
yarn strapi export --file backup-$(date +%Y%m%d-%H%M%S).tar.gz
```

**What gets exported:**

```
backup-20251202-103045.tar.gz/
├── schemas/                  # Content type definitions
│   ├── api::page.page.json
│   ├── api::navbar.navbar.json
│   └── ... (all content types)
├── entities/                 # Actual content data
│   ├── api.page.page.jsonl
│   ├── api.navbar.navbar.jsonl
│   └── ... (all entity data)
├── assets/                   # Media files
│   ├── image1.jpg
│   ├── image2.png
│   └── ... (all 331 files)
├── links/                    # Relationships
│   └── api.page.page.jsonl
├── configuration/            # Settings
│   ├── admin-users.json
│   └── permissions.json
└── metadata.json             # Export metadata
```

**Expected output:**

```bash
✔ schemas: 12 exported
✔ entities: 203 exported (size: 253 KB)
✔ assets: 331 exported (size: 27.4 MB)
✔ links: 355 exported (size: 68.5 KB)
✔ configuration: 91 exported (size: 221.6 KB)

Exported to: backup-20251202-103045.tar.gz
Total size: 28.1 MB
```

### Move Backup to Safe Location

```bash
# Create backups directory if it doesn't exist
mkdir -p backups/recovery

# Move backup
mv backup-20251202-103045.tar.gz backups/recovery/

# Verify it exists
ls -lh backups/recovery/
```

**Pro tip:** Store backups outside your project directory (external drive, cloud storage, etc.)

## Step 4: Perform Complete Database Recovery

### Scenario: You Just Lost Everything

Your database is now empty (or corrupted). Time to restore.

### Option A: Import Without Dropping Database (Safer)

This **adds** content from backup but doesn't delete existing data:

```bash
cd apps/strapi

# Import backup (merge mode)
yarn strapi import --file ../../backups/recovery/backup-20251202-103045.tar.gz
```

**Expected output:**

```bash
✔ schemas: 12 validated
✔ entities: 203 imported (size: 253 KB)
✔ assets: 331 uploaded (size: 27.4 MB)
✔ links: 355 restored (size: 68.5 KB)
✔ configuration: 91 applied (size: 221.6 KB)

Import completed successfully!
```

**Use this when:**

- You accidentally deleted specific content
- You want to restore without wiping other data
- You're not sure if backup is complete

### Option B: Force Import (Clean Slate)

This **deletes ALL existing content** first, then imports backup:

```bash
cd apps/strapi

# Import backup (force mode - DESTRUCTIVE)
yarn strapi import --file ../../backups/recovery/backup-20251202-103045.tar.gz --force
```

**⚠️ Warning:** `--force` flag drops all existing data before importing!

**Use this when:**

- Database is completely corrupted
- You want exact backup state (no extra data)
- You're certain backup has everything needed

## Step 8: Automate Backups (Prevention)

### Daily Backup Script (Recommended)

Create `scripts/backup-strapi-daily.sh`:

```bash
#!/bin/bash

# Daily Strapi backup script
# Usage: Run via cron job or manually

BACKUP_DIR="backups/recovery"
TIMESTAMP=$(date +%Y%m%d-%H%M%S)
FILENAME="daily-backup-${TIMESTAMP}.tar.gz"

# Navigate to Strapi directory
cd "$(dirname "$0")/../apps/strapi"

# Create backup
echo "Starting daily backup..."
yarn strapi export --file "${FILENAME}"

# Move to backup directory
mv "${FILENAME}" "../../${BACKUP_DIR}/"

echo "Backup completed: ${BACKUP_DIR}/${FILENAME}"

# Keep only last 7 days of backups
find "../../${BACKUP_DIR}" -name "daily-backup-*.tar.gz" -mtime +7 -delete

echo "Old backups cleaned (kept last 7 days)"
```

**Make executable:**

```bash
chmod +x scripts/backup-strapi-daily.sh
```

### Windows PowerShell Version

Create `scripts/backup-strapi-daily.ps1`:

```powershell
# Daily Strapi backup script (PowerShell)
# Usage: Run via Task Scheduler or manually

$BackupDir = "backups\recovery"
$Timestamp = Get-Date -Format "yyyyMMdd-HHmmss"
$Filename = "daily-backup-$Timestamp.tar.gz"

# Navigate to Strapi directory
Set-Location "$PSScriptRoot\..\apps\strapi"

# Create backup
Write-Host "Starting daily backup..."
yarn strapi export --file $Filename

# Move to backup directory
Move-Item $Filename "..\..\$BackupDir\"

Write-Host "Backup completed: $BackupDir\$Filename"

# Keep only last 7 days of backups
Get-ChildItem "..\..\$BackupDir\daily-backup-*.tar.gz" |
  Where-Object { $_.LastWriteTime -lt (Get-Date).AddDays(-7) } |
  Remove-Item

Write-Host "Old backups cleaned (kept last 7 days)"
```

### Add to package.json

```json
{
  "scripts": {
    "backup:daily": "bash scripts/backup-strapi-daily.sh",
    "backup:now": "cd apps/strapi && yarn strapi export --file ../../backups/recovery/manual-backup-$(date +%Y%m%d-%H%M%S).tar.gz"
  }
}
```

**Usage:**

```bash
# Manual backup anytime
yarn backup:now

# Daily automated backup
yarn backup:daily
```

### Schedule with Cron (Linux/macOS)

```bash
# Edit crontab
crontab -e

# Add daily backup at 2 AM
0 2 * * * cd /path/to/project && yarn backup:daily
```

### Schedule with Task Scheduler (Windows)

1. Open Task Scheduler
2. Create Basic Task
3. Trigger: Daily at 2:00 AM
4. Action: Start a Program
5. Program: `powershell.exe`
6. Arguments: `-File "C:\path\to\project\scripts\backup-strapi-daily.ps1"`

## Troubleshooting Common Issues

### Issue 1: "Cannot import: schema mismatch"

**Cause:** Backup was created with different Strapi version or content type definitions changed.

**Fix:**

```bash
# Import schemas only (without entities)
yarn strapi import --file backup.tar.gz --only schemas

# Then import entities
yarn strapi import --file backup.tar.gz --exclude schemas
```

### Issue 2: "Asset upload failed: disk space"

**Cause:** Not enough disk space for media files (27 MB in our case).

**Fix:**

```bash
# Check available space
df -h .

# Free up space or use external drive
mkdir /mnt/external/strapi-backups
mv backups/recovery/*.tar.gz /mnt/external/strapi-backups/
```

### Issue 3: "Relations not restored correctly"

**Cause:** Strapi imports entities before relationships are established.

**Fix:**

```bash
# Import with explicit order
yarn strapi import --file backup.tar.gz --force

# Rebuild admin panel
yarn strapi build --clean

# Restart Strapi
yarn dev
```

### Issue 4: "Media files missing after import"

**Cause:** Files were uploaded to cloud storage (AWS S3, Cloudinary) but backup only has URLs.

**Fix:** Strapi export includes local files only. For cloud storage:

1. **Option A:** Change to local upload provider before backup
2. **Option B:** Use cloud provider's backup tool (S3 bucket snapshot, Cloudinary backup)
3. **Option C:** Write script to download all media before export

```javascript
// Example: Download all media before export
const fs = require("fs")
const axios = require("axios")

async function downloadMedia() {
  const files = await strapi.documents("plugin::upload.file").findMany()

  for (const file of files) {
    const response = await axios.get(file.url, { responseType: "stream" })
    response.data.pipe(
      fs.createWriteStream(`public/uploads/${file.hash}${file.ext}`)
    )
  }
}
```

## Key Takeaways

✅ **Strapi export is perfect for content backups** (human-readable, cross-database)  
✅ **Always create backup before risky operations** (destructive scripts, major updates)  
✅ **Verify backups contain expected content** (extract and inspect)  
✅ **Use `--force` flag only when certain** (deletes existing data first)  
✅ **Automate daily backups** (cron jobs, Task Scheduler)  
✅ **Test restoration process before you need it** (dry run in development)

**Common Pitfalls:**

- ❌ Not creating backups regularly ("I'll do it tomorrow")
- ❌ Storing backups only on same machine (single point of failure)
- ❌ Never testing restoration (backup might be corrupted)
- ❌ Using `--force` flag without reading warnings
