# Tutorial: Implementing Idempotent Database Seeding

**Difficulty:** 🟡 Intermediate  
**Time to Complete:** 30 minutes  
**Platform:** Universal pattern (works with any ORM/database)

**What You'll Learn:**

- What "idempotent" means and why it matters for seed scripts
- The check-then-update pattern for safe seeding
- How to handle relationships in idempotent operations
- How to make seed scripts runnable multiple times without duplicates
- How to apply this pattern beyond just database seeding

**Prerequisites:**

- Understanding of database CRUD operations
- Basic async/await JavaScript knowledge
- Familiarity with ORMs (Strapi, Prisma, TypeORM, etc.)
- Completion of Tutorial 3.3 (Environment-Specific Seeding)

**Problem Statement:**

You have a seed script that creates test data. Every time you run it:

```bash
yarn seed:e2e:safe
```

It creates **duplicate** entries:

```
E2E Test Page (1st run)
E2E Test Page (2nd run)
E2E Test Page (3rd run)
...
```

**Why this is a problem:**

- Database fills with duplicate test data
- E2E tests fail (finds multiple matching elements)
- Manual cleanup required after each run
- Can't safely re-run seeds during development

**Solution:** Make seed scripts **idempotent** (safe to run multiple times).

---

## Step 1: Understanding Idempotence

### Definition

**Idempotent:** An operation that produces the same result regardless of how many times it's executed.

**Examples:**

```javascript
// ❌ NOT idempotent (duplicates every time)
await createPage({ title: "E2E Test Page", slug: "e2e-test" })

// ✅ Idempotent (same result every time)
const exists = await findPage({ slug: "e2e-test" })
if (exists) {
  await updatePage(exists.id, { title: "E2E Test Page" })
} else {
  await createPage({ title: "E2E Test Page", slug: "e2e-test" })
}
```

**Why it matters:**

- Can re-run seeds without fear of duplicates
- Safe to fix data during development
- CI can run seeds multiple times if needed
- Recovery from partial failures

## Step 2: The Destructive vs Safe Pattern

### Destructive Pattern (CI Only)

```typescript
// This is FINE for CI (fresh database every time)
export async function seedE2EData({ strapi }: { strapi: any }) {
  // Step 1: Delete everything
  await strapi.documents("api::page.page").deleteMany({})

  // Step 2: Create from scratch
  await strapi.documents("api::page.page").create({
    data: {
      title: "E2E Test Page",
      slug: "e2e-test-page",
      // ... all fields
    },
  })
}
```

**Result:** Same every time (because we start from zero)

**Problem:** Destroys existing content in development

### Idempotent Pattern (Development Safe)

```typescript
// This is SAFE for development (preserves existing content)
export async function seedE2EDataSafe({ strapi }: { strapi: any }) {
  // Step 1: Check if exists
  const existing = await strapi.documents("api::page.page").findMany({
    filters: { slug: { $eq: "e2e-test-page" } },
  })

  // Step 2: Update vs create
  if (existing && existing.length > 0) {
    // UPDATE existing page
    await strapi.documents("api::page.page").update({
      documentId: existing[0].documentId,
      data: getE2EPageData(),
    })
  } else {
    // CREATE new page
    await strapi.documents("api::page.page").create({
      data: getE2EPageData(),
    })
  }
}
```

**Result:** Same every time (but without deleting other content)

## Step 3: Implement Check-Then-Update Pattern

### Basic Pattern

```typescript
// STEP 1: Define unique identifier
const uniqueIdentifier = { slug: "e2e-test-page", locale: "en" }

// STEP 2: Check if entity exists
const existingEntities = await strapi
  .documents("api::page.page")
  .findMany({ filters: uniqueIdentifier })

// STEP 3: Update or create based on result
let entity

if (existingEntities && existingEntities.length > 0) {
  // Entity exists - UPDATE it
  entity = await strapi.documents("api::page.page").update({
    documentId: existingEntities[0].documentId,
    data: newData,
    locale: "en",
  })
  console.log(`✅ Updated: ${entity.title}`)
} else {
  // Entity doesn't exist - CREATE it
  entity = await strapi.documents("api::page.page").create({
    data: newData,
    locale: "en",
  })
  console.log(`✅ Created: ${entity.title}`)
}
```

### Complete Example with Error Handling

/**
 * Idempotent seed function for E2E test page
 */
export default async ({ strapi }: { strapi: any }) => {
  console.log("🌱 Starting idempotent E2E test data seeding...")

  try {
    // ====================================================================
    // 1. CHECK IF E2E TEST PAGE EXISTS
    // ====================================================================

    console.log("🔍 Checking for existing E2E test page...")

    const existingPages = await strapi.documents("api::page.page").findMany({
      filters: {
        slug: { $eq: "e2e-test-page" },
        locale: { $eq: "en" },
      },
      locale: "en",
    })

    let e2eTestPage

    // ====================================================================
    // 2. UPDATE OR CREATE
    // ====================================================================

    if (existingPages && existingPages.length > 0) {
      // Case 1: Page exists - UPDATE it
      console.log("✅ E2E test page found - updating...")

      e2eTestPage = await strapi.documents("api::page.page").update({
        documentId: existingPages[0].documentId,
        data: getE2EPageData(),
        locale: "en",
      })

      console.log(`✅ Updated page: ${e2eTestPage.title}`)
      console.log(`   Document ID: ${e2eTestPage.documentId}`)
    } else {
      // Case 2: Page doesn't exist - CREATE it
      console.log("📄 E2E test page not found - creating...")

      e2eTestPage = await strapi.documents("api::page.page").create({
        data: getE2EPageData(),
        locale: "en",
      })

      console.log(`✅ Created page: ${e2eTestPage.title}`)
      console.log(`   Document ID: ${e2eTestPage.documentId}`)
    }

    // ====================================================================
    // 3. PUBLISH THE PAGE
    // ====================================================================

    console.log("📤 Publishing E2E test page...")

    await strapi.documents("api::page.page").publish({
      documentId: e2eTestPage.documentId,
      locale: "en",
    })

    console.log("✅ Page published successfully")

    // ====================================================================
    // 4. SUCCESS SUMMARY
    // ====================================================================

    console.log("\n" + "=".repeat(60))
    console.log("🎉 Idempotent E2E Seeding Complete!")
    console.log("=".repeat(60))
    console.log(`✅ Page: ${e2eTestPage.title}`)
    console.log(`✅ Slug: /en/${e2eTestPage.slug}`)
    console.log(`✅ Status: Published`)
    console.log(`✅ Can be re-run safely (no duplicates)`)
    console.log("=".repeat(60) + "\n")
  } catch (error: any) {
    console.error("❌ Error during idempotent seeding:")
    console.error(error.message)

    // Log detailed validation errors if available
    if (error.details?.errors) {
      console.error("\n🔍 Validation errors:")
      error.details.errors.forEach((err: any, index: number) => {
        console.error(`Error ${index + 1}: ${JSON.stringify(err, null, 2)}`)
      })
    }

    throw error
  }
}

## Step 4: Handle Multiple Entities (Bulk Seeding)

### Pattern for Seeding Multiple Pages

```typescript
/**
 * Seed multiple pages idempotently
 */
export async function seedMultiplePages({ strapi }: { strapi: any }) {
  const pagesToSeed = [
    { title: "E2E Test Page", slug: "e2e-test-page" },
    { title: "E2E Contact Test", slug: "e2e-contact-test" },
    { title: "E2E Newsletter Test", slug: "e2e-newsletter-test" },
  ]

  for (const pageData of pagesToSeed) {
    console.log(`Processing: ${pageData.title}...`)

    // Check if page exists
    const existing = await strapi.documents("api::page.page").findMany({
      filters: { slug: { $eq: pageData.slug } },
    })

    if (existing && existing.length > 0) {
      // Update existing
      await strapi.documents("api::page.page").update({
        documentId: existing[0].documentId,
        data: pageData,
      })
      console.log(`✅ Updated: ${pageData.title}`)
    } else {
      // Create new
      await strapi.documents("api::page.page").create({
        data: pageData,
      })
      console.log(`✅ Created: ${pageData.title}`)
    }
  }

  console.log("✅ All pages seeded successfully")
}
```

## Step 5: Handle Relationships Idempotently

### Problem: Nested Relationships

```typescript
// Page has sections, sections have components
// How do we update without duplicating sections?
```

### Solution: Replace Content Entirely

```typescript
export async function seedPageWithSections({ strapi }: { strapi: any }) {
  const pageData = {
    title: "E2E Test Page",
    slug: "e2e-test-page",

    // Replace entire content array (idempotent)
    content: [
      { __component: "sections.hero", heading: "Hero Title" },
      { __component: "sections.features", heading: "Features" },
      // ... complete section definitions
    ],
  }

  // Find existing
  const existing = await strapi.documents("api::page.page").findMany({
    filters: { slug: { $eq: "e2e-test-page" } },
  })

  if (existing && existing.length > 0) {
    // Update replaces all sections
    await strapi.documents("api::page.page").update({
      documentId: existing[0].documentId,
      data: pageData, // This replaces content array entirely
    })
  } else {
    // Create with sections
    await strapi.documents("api::page.page").create({
      data: pageData,
    })
  }

  // Result: Same sections every time (no duplicates)
}
```

**Key principle:** When updating, provide **complete data structure**

export async function seedAPIToken({ strapi }: { strapi: any }) {
  const tokenData = {
    name: "E2E Test Readonly Token",
    description: "Token for E2E tests",
    type: "read-only",
    accessKey: hashToken("e2e-test-token-secret"), // Hash it!
  }

  // Check if token exists (by name - unique identifier)

    .documents("admin::api-token")

    // Update existing token
    await strapi.documents("admin::api-token").update({
      documentId: existing[0].documentId,
      data: tokenData,
    })
    console.log(`✅ Updated token: ${tokenData.name}`)
  } else {
    // Create new token
    await strapi.documents("admin::api-token").create({
      data: tokenData,
    })
    console.log(`✅ Created token: ${tokenData.name}`)

}

function hashToken(plainToken: string): string {
  const crypto = require("crypto")
  return crypto.createHash("sha512").update(plainToken).digest("hex")
}

## Step 8: Reusability Guide (Universal Pattern)

### Prisma Example

```typescript
// Idempotent user seeding with Prisma
export async function seedUser(prisma: PrismaClient) {
  const userData = {
    email: "test@example.com",
    name: "Test User",
  }

  // Upsert = update if exists, create if not
  const user = await prisma.user.upsert({
    where: { email: userData.email }, // Unique identifier
    update: userData, // Update existing
    create: userData, // Create new
  })

  console.log(`✅ Seeded user: ${user.email}`)
}
```

### TypeORM Example

```typescript
// Idempotent user seeding with TypeORM
export async function seedUser(userRepository: Repository<User>) {
  const userData = {
    email: "test@example.com",
    name: "Test User",
  }

  // Find by unique identifier
  let user = await userRepository.findOne({
    where: { email: userData.email },
  })

  if (user) {
    // Update existing
    await userRepository.update({ id: user.id }, userData)
    console.log(`✅ Updated user: ${userData.email}`)
  } else {
    // Create new
    user = userRepository.create(userData)
    await userRepository.save(user)
    console.log(`✅ Created user: ${userData.email}`)
  }
}
```

### Django Example

```python
# Idempotent model seeding in Django
from myapp.models import User

def seed_user():
    user_data = {
        'email': 'test@example.com',
        'name': 'Test User',
    }

    # Update or create (Django's built-in idempotent method)
    user, created = User.objects.update_or_create(
        email=user_data['email'],  # Unique identifier
        defaults=user_data         # Fields to update/create
    )

    if created:
        print(f'✅ Created user: {user.email}')
    else:
        print(f'✅ Updated user: {user.email}')
```

**Universal principle:** Check → Update or Create → Same result every time

## Key Takeaways

✅ **Idempotent = safe to run multiple times** (same result every time)  
✅ **Check-then-update pattern prevents duplicates** (find → update or create)  
✅ **Use unique identifiers for lookups** (slug, email, name)  
✅ **Replace entire nested structures** (content arrays, relationships)  
✅ **Test by running 3+ times** (should always have same count)  
✅ **Universal pattern across all ORMs** (Strapi, Prisma, TypeORM, Django)

**Common Pitfalls:**

- ❌ Forgetting to check for existing entities (causes duplicates)
- ❌ Using non-unique fields for lookup (finds wrong entity)
- ❌ Partial updates to nested structures (orphaned data)
- ❌ Not testing idempotence (run it 3 times!)
