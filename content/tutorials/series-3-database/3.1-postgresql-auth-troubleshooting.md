# Tutorial: Troubleshooting PostgreSQL Authentication for Strapi

**Difficulty:** 🟢 Beginner  
**Time to Complete:** 25 minutes  
**Platform:** Windows, Linux, macOS

**What You'll Learn:**

- How to diagnose PostgreSQL authentication failures
- The difference between MD5 and SCRAM-SHA-256 authentication
- How to modify `pg_hba.conf` safely on different platforms
- How to verify PostgreSQL service restart
- When to use MD5 vs SCRAM-SHA-256

**Prerequisites:**

- PostgreSQL 17 installed (or any version)
- Strapi project with PostgreSQL database
- Basic terminal/PowerShell knowledge
- Administrator/sudo access

**Problem Statement:**

You've created a PostgreSQL user and database for Strapi, but when you run `yarn dev` or `npm run dev`, you get:

```bash
Error: password authentication failed for user "strapi_user"
    at Connection.parseE (/node_modules/pg/lib/connection.js:674:13)
```

Yet pgAdmin connects fine with the same credentials. What gives?

---

## Step 1: Understand the Root Cause

PostgreSQL 17 changed the default authentication method from **MD5** to **SCRAM-SHA-256**.

**What this means:**

- When you create a user, PostgreSQL encrypts the password
- When you connect, PostgreSQL checks `pg_hba.conf` for which method to use
- If the stored password encryption doesn't match the authentication method, connection fails

**Why pgAdmin works:**

- pgAdmin tries multiple authentication methods automatically
- It has smart fallback logic

**Why Strapi/node-postgres doesn't:**

- Uses only the method specified in `pg_hba.conf`
- No automatic fallback

## Step 2: Locate Your pg_hba.conf File

### Windows

```powershell
# Find PostgreSQL installation
Get-Service postgresql* | Select-Object Name

# Common location:
# C:\Program Files\PostgreSQL\17\data\pg_hba.conf
```

**Typical path:** `C:\Program Files\PostgreSQL\17\data\pg_hba.conf`

### Linux

```bash
# Debian/Ubuntu
sudo find /etc/postgresql -name pg_hba.conf

# Red Hat/CentOS
sudo find /var/lib/pgsql -name pg_hba.conf
```

**Typical path:** `/etc/postgresql/17/main/pg_hba.conf`

### macOS (Homebrew)

```bash
# Find PostgreSQL data directory
brew info postgresql@17

# Common location:
# /opt/homebrew/var/postgresql@17/pg_hba.conf
```

**Typical path:** `/opt/homebrew/var/postgresql@17/pg_hba.conf` (Apple Silicon)  
**Or:** `/usr/local/var/postgresql@17/pg_hba.conf` (Intel)

## Step 4: Find and Modify Authentication Method

**Look for these lines (usually around line 82-83):**

```
# TYPE  DATABASE        USER            ADDRESS                 METHOD

# IPv4 local connections:
host    all             all             127.0.0.1/32            scram-sha-256
# IPv6 local connections:
host    all             all             ::1/128                 scram-sha-256
```

**Change to:**

```
# TYPE  DATABASE        USER            ADDRESS                 METHOD

# IPv4 local connections:
host    all             all             127.0.0.1/32            md5
# IPv6 local connections:
host    all             all             ::1/128                 md5
```

**What we changed:**

- `scram-sha-256` → `md5` (for localhost connections only)

**Why this works:**

- Most existing users were created before PostgreSQL 17
- Their passwords are stored as MD5 hashes
- Changing the authentication method to MD5 allows them to connect

**Save the file:**

- **Windows Notepad:** File → Save → Close
- **Linux/macOS nano:** `Ctrl+O` (write), `Enter`, `Ctrl+X` (exit)
- **vim:** `:wq` (write and quit)

## Troubleshooting Common Issues

### Issue 1: "Permission Denied" When Editing pg_hba.conf

**Cause:** Not running editor with administrator/sudo rights

**Fix:**

- **Windows:** Right-click Notepad → "Run as Administrator"
- **Linux/macOS:** Use `sudo` before command

### Issue 2: Service Won't Restart

**Windows:**

```powershell
# Check if service exists
Get-Service postgresql*

# If service name is different, use exact name:
Restart-Service postgresql-x64-17
```

**Linux:**

```bash
# Check PostgreSQL process
sudo systemctl status postgresql

# View error logs
sudo journalctl -u postgresql -n 50
```

**Common cause:** Syntax error in `pg_hba.conf`

- Re-open file and verify formatting
- Each line must have 5 columns (TYPE, DATABASE, USER, ADDRESS, METHOD)
- No extra spaces or missing tabs

### Issue 3: Still Getting Authentication Errors After Restart

**Check you modified the correct lines:**

```bash
# pg_hba.conf has multiple sections:
# - "local" (Unix socket connections)
# - "host" (TCP/IP connections)

# Strapi uses TCP/IP (host), not Unix sockets
# Make sure you changed the "host" lines, not "local" lines
```

**Before (wrong - this is for Unix sockets):**

```
local   all             all                                     scram-sha-256
```

**After (correct - this is for TCP/IP):**

```
host    all             all             127.0.0.1/32            md5
host    all             all             ::1/128                 md5
```

### Issue 4: "User Does Not Exist" Error

This is a different error. Your authentication is working, but the user hasn't been created yet.

**Fix:**

```sql
-- Connect to PostgreSQL as superuser (postgres)
-- Create the user:
CREATE USER strapi_user WITH PASSWORD 'your_password';
ALTER USER strapi_user WITH SUPERUSER;

-- Create database:
CREATE DATABASE strapi_dev OWNER strapi_user;
```

## Alternative: Recreate User with SCRAM-SHA-256 (Production Recommended)

If you're setting up a production environment, use SCRAM-SHA-256 (more secure):

**Step 1: Keep pg_hba.conf as scram-sha-256**

```
host    all             all             127.0.0.1/32            scram-sha-256
host    all             all             ::1/128                 scram-sha-256
```

**Step 2: Drop and recreate user**

```sql
-- Connect to postgres database (not strapi_dev)
psql -U postgres -d postgres

-- Drop existing database and user
DROP DATABASE IF EXISTS strapi_dev;
DROP USER IF EXISTS strapi_user;

-- Recreate with SCRAM-SHA-256 (default)
CREATE USER strapi_user WITH PASSWORD 'your_password';
ALTER USER strapi_user WITH SUPERUSER;
CREATE DATABASE strapi_dev OWNER strapi_user;
```

**Step 3: Restart PostgreSQL**

```bash
# Windows
Restart-Service postgresql-x64-17

# Linux
sudo systemctl restart postgresql

# macOS
brew services restart postgresql@17
```

**Step 4: Test connection**

```bash
cd apps/strapi
yarn dev
```

**Now the user password is stored as SCRAM-SHA-256, matching pg_hba.conf ✅**

## Security Considerations

### Development vs Production

**Development (localhost):**

- MD5 is acceptable (quick fix)
- Only accessible from your machine
- Convenience > strict security

**Production (remote servers):**

- Use SCRAM-SHA-256 (stronger encryption)
- Follow principle of least privilege
- Disable password authentication entirely (use certificate-based auth)

### Why SCRAM-SHA-256 is Better

| Feature              | MD5                   | SCRAM-SHA-256          |
| -------------------- | --------------------- | ---------------------- |
| **Encryption**       | Weak (1991 algorithm) | Strong (2017 standard) |
| **Rainbow Tables**   | Vulnerable            | Resistant              |
| **Salt**             | Yes (but predictable) | Yes (random)           |
| **Iterations**       | 1 round               | 4096 rounds (default)  |
| **Brute Force Time** | Hours-Days            | Months-Years           |
| **PostgreSQL 17**    | Legacy support        | Default recommendation |

**When to use MD5:**

- Local development only
- Quick fix to unblock yourself
- You understand the security trade-off

**When to use SCRAM-SHA-256:**

- Production environments
- Any remote database
- New projects (do it right from the start)

## Reusability Guide: Adapting This Pattern

This authentication debugging pattern applies to **any PostgreSQL connection**, not just Strapi:

### Node.js Applications (using `pg` library)

```javascript
// Same authentication applies
const { Pool } = require("pg")
const pool = new Pool({
  user: "your_user",
  host: "localhost",
  database: "your_db",
  password: "your_password",
  port: 5432,
})

// Will use authentication method from pg_hba.conf
```

### Django Applications

```python
# settings.py
DATABASES = {
    'default': {
        'ENGINE': 'django.db.backends.postgresql',
        'NAME': 'your_db',
        'USER': 'your_user',
        'PASSWORD': 'your_password',
        'HOST': 'localhost',
        'PORT': '5432',
    }
}

# Will use authentication method from pg_hba.conf
```

### Docker Containers

```yaml
# docker-compose.yml
services:
  postgres:
    image: postgres:17
    environment:
      POSTGRES_USER: strapi_user
      POSTGRES_PASSWORD: your_password
      POSTGRES_DB: strapi_dev
    volumes:
      - ./pg_hba.conf:/etc/postgresql/pg_hba.conf
    command: postgres -c hba_file=/etc/postgresql/pg_hba.conf
```

**Create `pg_hba.conf` in project root:**

```
# Custom pg_hba.conf for Docker
host    all             all             0.0.0.0/0               md5
```

## Key Takeaways

✅ **PostgreSQL 17 changed default authentication** from MD5 to SCRAM-SHA-256  
✅ **pg_hba.conf controls which method is used** for connections  
✅ **MD5 is fine for local development**, SCRAM-SHA-256 for production  
✅ **Always restart PostgreSQL service** after modifying `pg_hba.conf`  
✅ **pgAdmin hides this complexity** with automatic fallback, but most libraries don't

**Common Pitfalls:**

- ❌ Not restarting PostgreSQL after editing `pg_hba.conf`
- ❌ Editing the wrong section (local vs host)
- ❌ Using MD5 in production environments
- ❌ Not running editor with administrator/sudo rights
