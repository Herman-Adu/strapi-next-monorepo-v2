## Root Cause #1: Token Format Mismatch

### How Strapi Stores API Tokens

Strapi **does not** store API tokens as plaintext. It hashes them using SHA512 before storing in the database.

**Local seed script (wrong):**

```javascript
// ❌ BAD: Plaintext token
await strapi.db.query("admin::api-token").create({
  data: {
    name: "E2E Test Token",
    accessKey: "my-secret-token-12345", // Stored as plaintext
    type: "read-only",
  },
})
```

**What Strapi expects:**

```javascript
// ✅ GOOD: SHA512 hashed token
const crypto = require("crypto")
const plainToken = "my-secret-token-12345"
const hashedToken = crypto
  .createHash("sha512")
  .update(plainToken)
  .digest("base64") // or "hex" depending on Strapi version

await strapi.db.query("admin::api-token").create({
  data: {
    name: "E2E Test Token",
    accessKey: hashedToken, // SHA512 hash stored
    type: "read-only",
  },
})
```

### Why It Works Locally But Fails in CI

| Environment | Database State                                                                        | Seed Script Behavior                    | Result                          |
| ----------- | ------------------------------------------------------------------------------------- | --------------------------------------- | ------------------------------- |
| **Local**   | Persistent database with token already created (hashed correctly via Strapi admin UI) | Seed script skipped or fails gracefully | ✅ Works (using existing token) |
| **CI**      | Fresh database every run                                                              | Seed script creates plaintext token     | ❌ Fails (hash mismatch)        |

**The mismatch:**

- **Next.js sends:** `Authorization: Bearer my-secret-token-12345` (plaintext)
- **Strapi expects:** Hash of "my-secret-token-12345" to match database
- **Database has:** Plaintext "my-secret-token-12345" (wrong format)
- **Result:** Authentication fails with 401

## Step 1: Fix Token Hashing in Seed Script

### Implementation

```typescript
// File: apps/strapi/database/seeds/e2e-test-data.ts

import crypto from "crypto"

export default async ({ strapi }: { strapi: any }) => {
  console.log("🌱 Starting E2E test data seeding...")

  // ============================================================================
  // CREATE READ-ONLY API TOKEN FOR E2E TESTS
  // ============================================================================

  console.log("🔑 Creating read-only API token for E2E tests...")

  // Delete existing tokens to ensure clean state
  const existingTokens = await strapi.db
    .query("admin::api-token")
    .findMany({ where: { name: "e2e-readonly-token" } })

  for (const token of existingTokens) {
    await strapi.db
      .query("admin::api-token")
      .delete({ where: { id: token.id } })
    console.log(`   ♻️  Deleted existing token: ${token.name}`)
  }

  // The plaintext token (must match what's in .env files and CI secrets)
  const plainToken = "e2e-test-token-12345678901234567890123456789012"

  // Hash it with SHA512 (Strapi's internal format)
  const hashedToken = crypto
    .createHash("sha512")
    .update(plainToken)
    .digest("base64") // Use "base64" (some versions use "hex" - check your Strapi version)

  // Create API token with hashed accessKey
  const apiToken = await strapi.db.query("admin::api-token").create({
    data: {
      name: "e2e-readonly-token",
      description: "API token for E2E tests with full read access",
      type: "full-access", // or "read-only" depending on needs
      accessKey: hashedToken, // ✅ Store hashed version
      lifespan: null, // null = never expires
      permissions: [],
    },
  })

  console.log(`✅ API token created: ${apiToken.name}`)
  console.log(`   📝 Plain token: ${plainToken}`)
  console.log(
    `   💡 Set this in CI: STRAPI_REST_READONLY_API_KEY=${plainToken}`
  )

  // Continue with other seed data...
}
```

### Key Points

1. **Plaintext token:** Used in `.env.local` and GitHub secrets
2. **Hashed token:** Stored in database via seed script
3. **Strapi's flow:** Receives plaintext → hashes it → compares with database hash
4. **Match:** Authentication succeeds

### Verify Token Format

```bash
# Check what's in the database
$ psql -d strapi_dev -c "SELECT name, \"accessKey\" FROM admin_api_tokens;"

# Should see:
#       name          |                    accessKey (base64)
# --------------------+-------------------------------------------------------
# e2e-readonly-token  | lK7xH3... (long base64 string, ~88 characters)

# NOT this:
# e2e-readonly-token  | e2e-test-token-12345... (plaintext - WRONG!)
```

## Root Cause #2: Build-Time Environment Variables

Even with correct token hashing, you might still see 401 errors if environment variables aren't available during the build step.

### Understanding Next.js SSR Data Fetching

```typescript
// app/blog/[slug]/page.tsx - Next.js App Router example

export default async function BlogPost({ params }: { params: { slug: string } }) {
  // ⚠️ This fetch happens at BUILD TIME, not just at runtime!
  const response = await fetch(
    `${process.env.NEXT_PUBLIC_STRAPI_URL}/api/blogs/${params.slug}`,
    {
      headers: {
        Authorization: `Bearer ${process.env.STRAPI_REST_READONLY_API_KEY}`,
        // ↑ If undefined during build → 401 error baked into build output
      },
    }
  )

  const blog = await response.json()
  return <Article data={blog} />
}
```

**When this code runs:**

- ✅ During `yarn build` (static site generation)
- ✅ At revalidation time (ISR rebuilds)
- ✅ On-demand for dynamic routes

**If `STRAPI_REST_READONLY_API_KEY` is undefined during build:**

- API call fails with 401
- Error gets baked into build output
- Setting variable afterwards is too late

## Step 2: Fix Workflow Environment Variable Timing

### ❌ Wrong Order (Token After Build)

```yaml
# .github/workflows/ci.yml - BROKEN

- name: Build UI
  run: yarn workspace @repo/ui build
  # During build, process.env.STRAPI_REST_READONLY_API_KEY = undefined ❌
  # SSR routes fail to fetch data
  # Build "succeeds" but with error pages

- name: Set Environment Variables # TOO LATE!
  run: |
    echo "STRAPI_REST_READONLY_API_KEY=${{ secrets.STRAPI_API_TOKEN }}" >> apps/ui/.env.local
  # Token now available, but build already complete
```

### ✅ Correct Order (Token Before Build)

```yaml
# .github/workflows/ci.yml - FIXED

env:
  STRAPI_REST_READONLY_API_KEY: ${{ secrets.STRAPI_API_TOKEN }}

steps:
  - name: Checkout code
    uses: actions/checkout@v4

  - name: Setup Node.js
    uses: actions/setup-node@v4
    with:
      node-version: "20"

  - name: Install dependencies
    run: yarn --frozen-lockfile

  - name: Prepare Environment Variables # BEFORE BUILD! ✅
    run: |
      cp apps/strapi/.env.example apps/strapi/.env
      cp apps/ui/.env.local.example apps/ui/.env.local
      echo "STRAPI_REST_READONLY_API_KEY=${{ env.STRAPI_REST_READONLY_API_KEY }}" >> apps/ui/.env.local
      echo "NEXT_PUBLIC_STRAPI_URL=http://localhost:1337" >> apps/ui/.env.local

  - name: Build UI # Now has token available during build ✅
    run: yarn workspace @repo/ui build
    env:
      NODE_ENV: production

  - name: Run E2E Tests
    run: yarn test:e2e
    # Tests now pass - SSR routes have correct authentication
```

### Why This Order Matters

```
WRONG FLOW:
1. Build runs without token
2. SSR routes fetch with undefined token → 401
3. Build completes with broken pages
4. Token set (too late)
5. Tests fail (pages already built incorrectly)

CORRECT FLOW:
1. Token set in .env.local
2. Build runs with token available
3. SSR routes fetch with valid token → 200 OK
4. Build completes with correct pages
5. Tests pass (pages built correctly)
```

## Common Pitfalls & Solutions

### ❌ Pitfall 1: Wrong Hash Algorithm

**Problem:**

```javascript
const hashedToken = crypto.createHash("sha256").update(token).digest("hex")
// Using SHA256 instead of SHA512
```

**Solution:** Strapi uses SHA512 specifically. Check your Strapi version:

- Strapi v4: SHA512 with base64
- Strapi v3: SHA512 with hex (older versions)

```javascript
// Strapi v4 (current)
const hashedToken = crypto.createHash("sha512").update(token).digest("base64")

// Strapi v3 (legacy)
const hashedToken = crypto.createHash("sha512").update(token).digest("hex")
```

---

### ❌ Pitfall 2: Storing Plaintext Locally

**Problem:**

```javascript
// Local dev uses plaintext (works)
// CI uses hashed (fails)
// Inconsistent environments
```

**Solution:** Always use hashed tokens in seed scripts, regardless of environment:

```javascript
const isCI = process.env.CI === "true"
const token = isCI ? hashedToken : plainToken // ❌ NO!

// ✅ YES - always hash
const hashedToken = crypto
  .createHash("sha512")
  .update(plainToken)
  .digest("base64")
await createToken({ accessKey: hashedToken })
```

---

### ❌ Pitfall 3: Token Set After Build

**Problem:**

```yaml
- build
- set env vars # Too late
```

**Solution:** Always set environment variables BEFORE build:

```yaml
- set env vars # Do this first
- build # Now has vars available
```

---

### ❌ Pitfall 4: Not Matching .env and Secrets

**Problem:**

```bash
# .env.local
STRAPI_REST_READONLY_API_KEY=token-A

# GitHub Secrets
STRAPI_API_TOKEN=token-B

# Mismatch = authentication fails
```

**Solution:** Use same plaintext token everywhere:

```bash
# Generate once
$ node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"

# Use in:
# - .env.local (local development)
# - GitHub Actions secrets (CI)
# - Seed script (hash this value)
```

## Reusability Guide

This pattern applies to **any system using hashed credentials**.

### User Password Seeding

```javascript
const bcrypt = require("bcrypt")

const plainPassword = "TestUser123!"
const hashedPassword = await bcrypt.hash(plainPassword, 10)

await createUser({
  email: "test@example.com",
  password: hashedPassword, // Store hash, not plaintext
})
```

### JWT Secrets

```javascript
const crypto = require("crypto")

const secret = process.env.JWT_SECRET
const hashedSecret = crypto.createHash("sha256").update(secret).digest("hex")

// Use hashed version in database
```

### Custom Auth Tokens

```javascript
// Any token system with hashing
const customHash = crypto
  .createHash(algorithm) // Match your system's algorithm
  .update(plainToken)
  .digest(encoding) // Match your system's encoding
```

**Universal principle:** Seed data must match production storage format (hashing, encryption, encoding).
