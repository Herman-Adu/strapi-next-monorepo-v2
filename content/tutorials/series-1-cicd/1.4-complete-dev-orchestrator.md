## Step 3: Docker Detection

```javascript
function checkDockerRunning() {
  return new Promise((resolve) => {
    const dockerCheck = spawn("docker", ["info"], { shell: true })

    dockerCheck.on("close", (code) => {
      resolve(code === 0) // 0 = Docker running, non-zero = not running
    })

    dockerCheck.on("error", () => {
      resolve(false) // Command failed = Docker not installed/running
    })
  })
}
```

**Why check Docker:**

- Docker can't be auto-started programmatically on all platforms
- Fail fast with clear error if Docker not running
- Exit code 0 = daemon running, 1 = daemon not running

**Usage in main:**

```javascript
const dockerRunning = await checkDockerRunning()
if (!dockerRunning) {
  log("❌ Docker is not running!", colors.red)
  log("   Please start Docker Desktop and try again.", colors.red)
  process.exit(1)
}
```

## Step 4: Database Orchestration

```javascript
function startDockerDatabase() {
  return new Promise((resolve, reject) => {
    log("\n🐳 Starting PostgreSQL database via Docker Compose...", colors.cyan)

    const dockerCompose = spawn("docker", ["compose", "up", "-d", "db"], {
      cwd: path.join(__dirname, "../apps/strapi"), // Where docker-compose.yml lives
      shell: true,
      stdio: "inherit", // Show Docker output in terminal
    })

    dockerCompose.on("close", (code) => {
      if (code === 0) {
        log("✅ Database started successfully!\n", colors.green)
        // Wait 3 seconds for PostgreSQL to initialize
        setTimeout(() => resolve(), 3000)
      } else {
        reject(new Error(`Docker Compose exited with code ${code}`))
      }
    })

    dockerCompose.on("error", (err) => {
      reject(err)
    })
  })
}
```

**Key decisions:**

- `-d` flag: Detached mode (runs in background)
- `cwd`: Run command in strapi directory (where docker-compose.yml is)
- `stdio: "inherit"`: Show Docker output (useful for debugging)
- 3-second wait: Empirical testing showed PostgreSQL needs 2-3s to accept connections

## Step 5: Health Check Implementation

### HTTP Health Check Function

```javascript
function checkStrapiRunning() {
  return new Promise((resolve) => {
    const options = {
      host: "localhost",
      port: 1337,
      path: "/admin",
      method: "GET",
      timeout: 1000, // 1-second timeout
    }

    const req = http.request(options, (res) => {
      // 200 OK or 302 Redirect = Strapi ready
      resolve(res.statusCode === 200 || res.statusCode === 302)
    })

    req.on("error", () => {
      resolve(false) // Connection refused = not ready
    })

    req.on("timeout", () => {
      req.destroy()
      resolve(false) // Timeout = not ready
    })

    req.end()
  })
}
```

**Why `/admin` endpoint:**

- Port 1337 might listen before Strapi fully initialized
- `/admin` only responds when Strapi completely ready
- Returns 200 OK or 302 Redirect (both acceptable)

### Polling Loop with Exponential Backoff

```javascript
function waitForStrapi(maxAttempts = 60, interval = 2000) {
  return new Promise((resolve, reject) => {
    let attempts = 0

    const check = async () => {
      attempts++

      if (attempts > maxAttempts) {
        reject(new Error("Strapi did not start within the expected time"))
        return
      }

      const isRunning = await checkStrapiRunning()

      if (isRunning) {
        log("✅ Strapi is ready!\n", colors.green)
        resolve()
      } else {
        // Log progress every 5 attempts (every 10 seconds)
        if (attempts % 5 === 0) {
          log(
            `⏳ Waiting for Strapi... (attempt ${attempts}/${maxAttempts})`,
            colors.yellow
          )
        }
        setTimeout(check, interval)
      }
    }

    check()
  })
}
```

**Configuration:**

- `maxAttempts = 60`: 60 × 2s = 2-minute timeout
- `interval = 2000`: Check every 2 seconds
- Log every 5 attempts: Prevents console spam

## Step 6: Process Spawning

### Start Strapi Backend

```javascript
function startStrapi() {
  return new Promise((resolve, reject) => {
    log("🚀 Starting Strapi backend...", colors.blue)

    const strapi = spawn(
      "yarn",
      ["workspace", "@repo/strapi", "run", "develop"],
      {
        shell: true,
        stdio: ["ignore", "pipe", "pipe"],
        // stdin: ignore, stdout: pipe, stderr: pipe
      }
    )

    // Forward stdout with prefix
    strapi.stdout.on("data", (data) => {
      const message = data.toString()
      process.stdout.write(`${colors.blue}[Strapi]${colors.reset} ${message}`)
    })

    // Forward stderr with prefix
    strapi.stderr.on("data", (data) => {
      const message = data.toString()
      process.stderr.write(`${colors.blue}[Strapi]${colors.reset} ${message}`)
    })

    // Return process handle after 2 seconds (don't wait for exit)
    setTimeout(() => resolve(strapi), 2000)

    strapi.on("error", (err) => {
      reject(err)
    })
  })
}
```

**stdio handling:**

- `stdin: ignore`: Strapi doesn't need user input
- `stdout: pipe`: Capture output for prefixing
- `stderr: pipe`: Capture errors for prefixing
- Prefix with `[Strapi]`: Clear which service logged what

### Start Next.js UI

```javascript
function startUI() {
  log("⚛️  Starting Next.js UI...", colors.cyan)

  const ui = spawn("yarn", ["workspace", "@repo/ui", "run", "dev"], {
    shell: true,
    stdio: "inherit", // Next.js already has nice formatting
  })

  return ui
}
```

**Why `stdio: "inherit"` for UI:**

- Next.js dev server has colorful, formatted output
- Let it show directly without prefixing
- Clearer for developers debugging frontend

## Step 7: Main Orchestration Flow

```javascript
async function main() {
  let strapiProcess, uiProcess

  try {
    log(`\n${"=".repeat(60)}`, colors.bright)
    log("🎯 Development Environment Orchestrator", colors.bright)
    log(`${"=".repeat(60)}\n`, colors.bright)

    // Step 1: Check Docker
    log("1️⃣  Checking Docker status...", colors.yellow)
    const dockerRunning = await checkDockerRunning()
    if (!dockerRunning) {
      log("❌ Docker is not running!", colors.red)
      log("   Please start Docker Desktop and try again.", colors.red)
      process.exit(1)
    }
    log("✅ Docker is running\n", colors.green)

    // Step 2: Start database
    log("2️⃣  Starting database...", colors.yellow)
    await startDockerDatabase()

    // Step 3: Start Strapi
    log("3️⃣  Starting Strapi...", colors.yellow)
    strapiProcess = await startStrapi()

    // Step 4: Wait for Strapi to be ready (CRITICAL!)
    log("4️⃣  Waiting for Strapi to be ready...", colors.yellow)
    await waitForStrapi()

    // Step 5: Start UI (safe now because Strapi is ready)
    log("5️⃣  Starting UI...", colors.yellow)
    uiProcess = startUI()

    // Success message
    log("\n" + "=".repeat(60), colors.bright)
    log("✅ All services started successfully!", colors.green)
    log("=".repeat(60) + "\n", colors.bright)
    log("📍 Strapi Admin: http://localhost:1337/admin", colors.cyan)
    log("📍 Next.js UI:   http://localhost:3000", colors.cyan)
    log("\n💡 Press Ctrl+C to stop all services\n", colors.yellow)

    // Graceful shutdown
    const cleanup = () => {
      log("\n\n🛑 Shutting down services...", colors.yellow)
      if (strapiProcess && !strapiProcess.killed) {
        strapiProcess.kill("SIGTERM")
      }
      if (uiProcess && !uiProcess.killed) {
        uiProcess.kill("SIGTERM")
      }
      process.exit(0)
    }

    process.on("SIGINT", cleanup) // Ctrl+C
    process.on("SIGTERM", cleanup) // Kill command
  } catch (error) {
    log(`\n❌ Error: ${error.message}`, colors.red)
    process.exit(1)
  }
}

main()
```

**Flow breakdown:**

1. ✅ Verify Docker (exit early if not running)
2. ✅ Start PostgreSQL (wait 3s for initialization)
3. ✅ Start Strapi (get process handle, don't wait for exit)
4. ✅ **Wait for Strapi health check** (critical - ensures ready)
5. ✅ Start Next.js UI (safe now because Strapi ready)
6. ✅ Display URLs and wait
7. ✅ Graceful shutdown on Ctrl+C

## Common Pitfalls & Solutions

### ❌ Pitfall 1: Not Waiting for Health Check

**Problem:**

```javascript
await startStrapi()
startUI() // Started immediately, Strapi not ready yet
```

**Result:** UI tries to connect to Strapi, gets connection errors

**Solution:**

```javascript
await startStrapi()
await waitForStrapi() // Wait for health check!
startUI() // Safe now
```

---

### ❌ Pitfall 2: Using Port Checks Instead of HTTP

**Problem:**

```javascript
// Check if port 1337 is listening
const isPortOpen = await checkPort(1337) // Returns true
startUI() // But Strapi might still be initializing!
```

**Solution:** Use HTTP health check (tests application-level readiness)

---

### ❌ Pitfall 3: No Graceful Shutdown

**Problem:**

```javascript
// Just let processes run
// User hits Ctrl+C
// Orphaned processes keep running
```

**Solution:**

```javascript
process.on("SIGINT", () => {
  strapiProcess.kill("SIGTERM")
  uiProcess.kill("SIGTERM")
  process.exit(0)
})
```

---

### ❌ Pitfall 4: Cross-Platform Path Issues

**Problem:**

```javascript
cwd: "../apps/strapi" // Breaks on Windows
```

**Solution:**

```javascript
cwd: path.join(__dirname, "../apps/strapi") // Cross-platform
```
