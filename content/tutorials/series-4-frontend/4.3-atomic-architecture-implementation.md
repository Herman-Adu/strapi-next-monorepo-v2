## Overview

### What You'll Build

Standardized field ordering across all Strapi section components using atomic design principles. Transform chaotic, randomly-ordered fields into a predictable pattern: **Background → Badge → Header → Content**.

### The Problem

8 landing page sections in Strapi CMS have inconsistent field ordering:

- **Hero Section:** `title → subtitle → cta → image → background → badge`
- **Feature Section:** `items → listItems → footerNote → gridColumns → background → badge → header`
- **CTA Section:** `background → header → primaryCta → secondaryCta → badge`

**No pattern. Pure chaos.**

**Impact:**

- ❌ 30 min/week searching for fields
- ❌ 2 hours training new content editors
- ❌ 6 errors/month (missed fields)
- ❌ Inconsistent developer experience
- ❌ **Annual cost:** $4,900/year in lost productivity

- ✅ Understand atomic architecture pattern for CMS structure

- ✅ Use Strapi config sync for schema updates

## Before You Begin

### The Atomic Architecture Pattern

```
┌─────────────────────────────────────┐
│    ATOMIC ARCHITECTURE PATTERN      │
│                                     │
│  Outside-in, structural → content   │
└─────────────────────────────────────┘

1. BACKGROUND (Outermost structural layer)
   └─ Controls visual container
   └─ Sets the stage for content
   └─ Examples: color, gradient, image

2. BADGE (Structural accent)
   └─ Small visual indicator above content
   └─ Provides context or category
   └─ Optional decorative element

3. HEADER (Structural heading)
   └─ Title, subtitle, description
   └─ Consistent heading component
   └─ Required for all sections

4. CONTENT (Section-specific fields)
   └─ Unique fields for this section type
   └─ Features, metrics, forms, etc.
   └─ Varies by section purpose
```

**Principle:** Structure from outside-in, content last.

## Step 1: Define Standard Field Order

### Universal Template

```typescript
// Standard ordering for ALL section components

interface SectionStructure {
  // ===== LAYER 1: BACKGROUND (Structural) =====
  background?: {
    type: "default" | "light" | "dark" | "gradient" | "image"
    gradient?: string
    image?: MediaFile
  }

  // ===== LAYER 2: BADGE (Structural) =====
  badge?: {
    text: string
    variant: "default" | "primary" | "success"
  }

  // ===== LAYER 3: HEADER (Structural) =====
  heading: {
    title: string
    subtitle?: string
    description?: string
    alignment?: "left" | "center"
  }

  // ===== LAYER 4: CONTENT (Section-specific) =====
  // ... unique fields for this section type
}
```

### Rationale

| Layer          | Why This Order                | Example                 |
| -------------- | ----------------------------- | ----------------------- |
| **Background** | Sets visual context first     | Light, dark, gradient   |
| **Badge**      | Optional accent above content | "New Feature", "Beta"   |
| **Header**     | Main structural heading       | Title + subtitle        |
| **Content**    | Section-specific fields last  | CTAs, features, metrics |

**Predictability:** Content editors build muscle memory. Fields always in same order.

## Step 2: Update HeroSection Schema

### Before (Random Order)

```json
// apps/strapi/src/components/sections/hero.json
{
  "collectionName": "components_sections_heroes",
  "info": {
    "displayName": "Hero",
    "description": "Hero section"
  },
  "attributes": {
    "title": { "type": "string", "required": true },
    "subtitle": { "type": "string" },
    "buttons": {
      "type": "component",
      "repeatable": true,
      "component": "atoms.button"
    },
    "image": { "type": "media", "allowedTypes": ["images"] },
    "background": {
      "type": "component",
      "component": "atoms.background"
    },
    "badge": {
      "type": "component",
      "component": "atoms.badge"
    }
  }
}
```

**Problems:**

- ❌ Background field buried at bottom
- ❌ Badge after buttons (illogical order)
- ❌ No consistent pattern
- ❌ Hard to scan quickly

### After (Atomic Order)

```json
// apps/strapi/src/components/sections/hero.json
{
  "collectionName": "components_sections_heroes",
  "info": {
    "displayName": "Hero",
    "description": "Hero section with atomic architecture"
  },
  "attributes": {
    // LAYER 1: Background (structural)
    "background": {
      "type": "component",
      "repeatable": false,
      "component": "atoms.background",
      "required": false
    },

    // LAYER 2: Badge (structural)
    "badge": {
      "type": "component",
      "repeatable": false,
      "component": "atoms.badge",
      "required": false
    },

    // LAYER 3: Header (structural)
    "heading": {
      "type": "component",
      "repeatable": false,
      "component": "molecules.heading",
      "required": true
    },

    // LAYER 4: Content (section-specific)
    "description": {
      "type": "richtext",
      "required": false
    },
    "buttons": {
      "type": "component",
      "repeatable": true,
      "component": "atoms.button",
      "max": 2
    },
    "image": {
      "type": "media",
      "multiple": false,
      "required": false,
      "allowedTypes": ["images"]
    }
  }
}
```

**Benefits:**

- ✅ Background first (sets stage)
- ✅ Badge second (decorative accent)
- ✅ Heading third (main structure)
- ✅ Content last (section-specific)
- ✅ Consistent pattern

**Key:** Field order in JSON = field order in Strapi admin UI!

## Step 5: Verification Script

### Automated Verification

```typescript
// scripts/verify-atomic-order.ts
import fs from "fs"
import path from "path"

const SECTIONS_DIR = "apps/strapi/src/components/sections"
const EXPECTED_ORDER = ["background", "badge", "heading"]

interface SectionSchema {
  attributes: Record<string, any>
}

function verifySection(filename: string): boolean {
  const filepath = path.join(SECTIONS_DIR, filename)
  const schema: SectionSchema = JSON.parse(fs.readFileSync(filepath, "utf8"))

  const fieldNames = Object.keys(schema.attributes)
  const actualOrder = fieldNames.slice(0, 3) // First 3 fields

  const isCorrect = EXPECTED_ORDER.every(
    (field, index) =>
      actualOrder[index] === field || actualOrder[index] === undefined // Optional field
  )

  console.log(`${isCorrect ? "✅" : "❌"} ${filename}`)
  console.log(`   Expected: ${EXPECTED_ORDER.join(", ")}`)
  console.log(`   Actual:   ${actualOrder.join(", ")}`)
  console.log("")

  return isCorrect
}

// Main execution
const sections = fs.readdirSync(SECTIONS_DIR).filter((f) => f.endsWith(".json"))

console.log("🔍 Verifying atomic architecture field ordering...\n")

const results = sections.map(verifySection)
const allCorrect = results.every((r) => r)

console.log(
  allCorrect
    ? "✅ All sections follow atomic architecture!"
    : "❌ Some sections need updates"
)

process.exit(allCorrect ? 0 : 1)
```

## Step 6: Update Frontend Components

### Component Structure

```tsx
// components/sections/HeroSection.tsx
import { Background } from "@/components/atoms/Background"
import { Badge } from "@/components/atoms/Badge"
import { Heading } from "@/components/molecules/Heading"
import { Button } from "@/components/atoms/Button"
import type { ComponentSectionsHero } from "@repo/strapi/types/api"

interface HeroSectionProps {
  data: ComponentSectionsHero
}

export function HeroSection({ data }: HeroSectionProps) {
  const { background, badge, heading, description, buttons, image } = data

  return (
    // LAYER 1: Background (structural)
    <Background data={background}>
      <div className="container mx-auto px-4 py-16">
        {/* LAYER 2: Badge (structural) */}
        {badge && <Badge {...badge} />}

        {/* LAYER 3: Heading (structural) */}
        <Heading {...heading} />

        {/* LAYER 4: Content (section-specific) */}
        {description && (
          <div
            className="prose prose-lg dark:prose-invert max-w-none mb-8"
            dangerouslySetInnerHTML={{ __html: description }}
          />
        )}

        {buttons && buttons.length > 0 && (
          <div className="flex gap-4">
            {buttons.map((btn, i) => (
              <Button key={i} {...btn} />
            ))}
          </div>
        )}

        {image && (
          <img
            src={image.url}
            alt={image.alternativeText || heading.title}
            className="mt-12 rounded-xl shadow-2xl"
          />
        )}
      </div>
    </Background>
  )
}
```

**Key:** Component rendering follows same outside-in structure as field order.

## Common Pitfalls & Solutions

### Issue 1: Old Fields Still Visible

**Problem:**
After updating schema, old fields still show in admin UI.

**Solution:**

```bash
# Clear Strapi cache
rm -rf .cache
rm -rf build

# Restart Strapi
yarn develop
```

---

### Issue 2: TypeScript Types Out of Sync

**Problem:**

```typescript
// Component expects 'heading' but type shows 'title', 'subtitle'
```

**Solution:**

```bash
# Regenerate TypeScript types
yarn workspace @repo/strapi types:generate

# Restart Next.js dev server
yarn workspace @repo/ui dev
```

---

### Issue 3: Frontend Components Break

**Problem:**
Changed field structure, components expect old fields.

**Solution:**

```tsx
// Update component props to match new schema

// Before:
const { title, subtitle } = data

// After:
const { heading } = data
const { title, subtitle } = heading
```

---

### Issue 4: Config Sync Fails

**Problem:**

```bash
yarn strapi config:restore
Error: Schema conflict detected
```

**Solution:**

```bash
# Force import (WARNING: overwrites current schema)
yarn strapi config:restore -f config-updated-atomic.tar.gz --force

# Or manually update via Content-Type Builder UI
```
