## Overview

### What You'll Build

Editor-configurable grid layouts for Strapi section components. Add a `gridColumns` enumeration field allowing content editors to choose between 2, 3, 4, or 6 column layouts without developer intervention.

### The Problem

MetricsSection hardcoded to 3-column grid. Every layout change request requires:

- Developer creates new branch
- Updates component code
- Tests responsive breakpoints
- Creates PR, waits for review
- Deploys to production

**Developer bottleneck:** ~2 hours per layout change request  
**Frequency:** ~12 requests/year  
**Annual cost:** $2,400/year (24 hours × $100/hr)

- ✅ Create dynamic Tailwind grid classes
- ✅ Handle responsive breakpoints for all grid sizes
- ✅ Empower content editors to control layouts
- ✅ Eliminate developer bottleneck (100% time savings)

- Strapi Content-Type Builder knowledge

### What We're Building

```tsx
// ✅ Dynamic grid with editor control
// components/sections/MetricsSection.tsx

export function MetricsSection({ data }: MetricsSectionProps) {
  const { metrics, gridColumns } = data // ← gridColumns from CMS

  // Dynamic grid classes based on editor's choice
  const gridClass = GRID_COLUMNS[gridColumns] || GRID_COLUMNS["3"]

  return (
    <div className="container mx-auto px-4 py-16">
      <div className={`grid ${gridClass} gap-8`}>
        {metrics.map((metric, index) => (
          <StatCard key={index} {...metric} />
        ))}
      </div>
    </div>
  )
}

// Benefits:
// ✅ Content editor chooses grid layout
// ✅ No developer intervention needed
// ✅ Instant layout changes
```

- `enum: ["2", "3", "4", "6"]` → available options
- `default: "3"` → safe default (most common layout)
- `required: true` → prevent empty values

## Step 4: Create Grid Class Mapping

### Basic Grid Mapping

```tsx
// components/sections/MetricsSection.tsx

// Grid column class mapping
const GRID_COLUMNS: Record<string, string> = {
  "2": "grid-cols-1 md:grid-cols-2",
  "3": "grid-cols-1 md:grid-cols-2 lg:grid-cols-3",
  "4": "grid-cols-1 md:grid-cols-2 lg:grid-cols-4",
  "6": "grid-cols-2 md:grid-cols-3 lg:grid-cols-6",
}
```

**Responsive logic:**

| Grid Cols | Mobile (<768px) | Tablet (768-1024px) | Desktop (>1024px) |
| --------- | --------------- | ------------------- | ----------------- |
| **2**     | 1 column        | 2 columns           | 2 columns         |
| **3**     | 1 column        | 2 columns           | 3 columns         |
| **4**     | 1 column        | 2 columns           | 4 columns         |
| **6**     | 2 columns       | 3 columns           | 6 columns         |

**Design rationale:**

- Mobile: 1 column (readable, no horizontal scroll)
- Tablet: 2-3 columns (balanced)
- Desktop: Full grid (utilize screen space)

## Step 5: Update Component

### Full Implementation

```tsx
// components/sections/MetricsSection.tsx
import { Background } from "@/components/atoms/Background"
import { Badge } from "@/components/atoms/Badge"
import { Heading } from "@/components/molecules/Heading"
import { StatCard } from "@/components/molecules/StatCard"
import type { ComponentSectionsMetrics } from "@repo/strapi/types/api"

interface MetricsSectionProps {
  data: ComponentSectionsMetrics
}

// Grid column class mapping
const GRID_COLUMNS: Record<string, string> = {
  "2": "grid-cols-1 md:grid-cols-2",
  "3": "grid-cols-1 md:grid-cols-2 lg:grid-cols-3",
  "4": "grid-cols-1 md:grid-cols-2 lg:grid-cols-4",
  "6": "grid-cols-2 md:grid-cols-3 lg:grid-cols-6",
}

export function MetricsSection({ data }: MetricsSectionProps) {
  const { background, badge, heading, metrics, gridColumns } = data

  // Get dynamic grid class (with fallback)
  const gridClass = GRID_COLUMNS[gridColumns] || GRID_COLUMNS["3"]

  return (
    <Background data={background}>
      <div className="container mx-auto px-4 py-16">
        {/* Badge (optional) */}
        {badge && <Badge {...badge} className="mb-4" />}

        {/* Heading */}
        <Heading {...heading} className="mb-12" />

        {/* Dynamic grid */}
        <div className={`grid ${gridClass} gap-8`}>
          {metrics.map((metric, index) => (
            <StatCard key={index} {...metric} />
          ))}
        </div>
      </div>
    </Background>
  )
}
```

**Key features:**

- ✅ Dynamic `gridClass` based on CMS choice
- ✅ Fallback to 3-column if invalid value
- ✅ Type-safe (TypeScript prevents invalid `gridColumns` values)
- ✅ Responsive breakpoints handled

## Step 6: Advanced Grid Variations

### Variable Gap Sizes

```tsx
// Different gap sizes for different grid densities
const GRID_GAP: Record<string, string> = {
  "2": "gap-12", // Larger gap for 2-column (more breathing room)
  "3": "gap-8", // Medium gap for 3-column
  "4": "gap-6", // Smaller gap for 4-column
  "6": "gap-4", // Tight gap for 6-column
}

export function MetricsSection({ data }: MetricsSectionProps) {
  const { gridColumns, metrics } = data

  const gridClass = GRID_COLUMNS[gridColumns]
  const gapClass = GRID_GAP[gridColumns]

  return (
    <div className={`grid ${gridClass} ${gapClass}`}>
      {metrics.map((metric, index) => (
        <StatCard key={index} {...metric} />
      ))}
    </div>
  )
}
```

## Common Pitfalls & Solutions

### Issue 1: Grid Classes Not Applying

**Problem:**

```tsx
// Tailwind not recognizing dynamic classes
const gridClass = `grid-cols-${gridColumns}` // ❌ Doesn't work
```

**Solution:**

```tsx
// Use complete class strings
const GRID_COLUMNS: Record<string, string> = {
  "2": "grid-cols-1 md:grid-cols-2", // ✅ Full class strings
  "3": "grid-cols-1 md:grid-cols-2 lg:grid-cols-3",
}
```

**Why:** Tailwind's purge system needs to see complete class names in source code. Dynamic string concatenation breaks tree-shaking.

---

### Issue 2: TypeScript Error

**Problem:**

```typescript
// Type error: 'gridColumns' doesn't exist
const { gridColumns } = data // ❌
```

**Solution:**

```bash
# Regenerate types after schema change
yarn workspace @repo/strapi types:generate

# Restart Next.js dev server
yarn workspace @repo/ui dev
```

---

### Issue 3: Layout Breaks on Mobile

**Problem:**
6-column grid causes horizontal scroll on mobile.

**Solution:**

```tsx
// Always start with fewer columns on mobile
const GRID_COLUMNS: Record<string, string> = {
  "6": "grid-cols-2 md:grid-cols-3 lg:grid-cols-6", // ✅ 2 cols on mobile
  // NOT: 'grid-cols-6'  // ❌ Would break mobile
}
```

---

### Issue 4: Missing Fallback

**Problem:**
If `gridColumns` is empty or invalid, grid breaks.

**Solution:**

```tsx
// Always provide fallback
const gridClass = GRID_COLUMNS[gridColumns] || GRID_COLUMNS["3"] // ✅

// Or with validation
const safeGridColumns = ["2", "3", "4", "6"].includes(gridColumns)
  ? gridColumns
  : "3"
```

## Reusability Template

### Universal Grid Schema

```json
{
  "gridColumns": {
    "type": "enumeration",
    "enum": ["2", "3", "4", "6"],
    "default": "3",
    "required": true
  }
}
```

### Universal Grid Component Logic

```tsx
// Reusable hook for any grid section
function useGridColumns(columns: string) {
  const GRID_MAP: Record<string, string> = {
    "2": "grid-cols-1 md:grid-cols-2",
    "3": "grid-cols-1 md:grid-cols-2 lg:grid-cols-3",
    "4": "grid-cols-1 md:grid-cols-2 lg:grid-cols-4",
    "6": "grid-cols-2 md:grid-cols-3 lg:grid-cols-6",
  }

  return GRID_MAP[columns] || GRID_MAP["3"]
}

// Usage in any component:
export function AnySection({ data }: AnySectionProps) {
  const gridClass = useGridColumns(data.gridColumns)

  return (
    <div className={`grid ${gridClass} gap-8`}>
      {data.items.map((item, i) => (
        <Item key={i} {...item} />
      ))}
    </div>
  )
}
```
