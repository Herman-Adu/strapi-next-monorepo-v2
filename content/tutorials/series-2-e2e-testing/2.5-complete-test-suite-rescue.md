## Phase 2: Fix Issues Systematically (One at a Time!)

### Issue #1: CI Authentication (42 tests, 100% CI failure rate)

**Symptoms:**

- All tests pass locally
- All tests fail in GitHub Actions
- Error: `401 Unauthorized` on API calls

**Root Cause Discovery:**

```bash
# Check GitHub Actions logs
# Line 45: "Building UI... (no API token set yet)"
# Line 87: "Running E2E tests... (401 errors)"
#
# AHA! Token set AFTER build, but SSR fetches data DURING build!
```

**Fix:**

```yaml
# .github/workflows/ci.yml

# ❌ WRONG ORDER (token too late)
- name: Build UI
  run: yarn build
- name: Set API token
  run: echo "API_KEY=${{ secrets.TOKEN }}" >> .env

# ✅ CORRECT ORDER (token before build)
- name: Set API token # ← MOVED BEFORE BUILD
  run: echo "API_KEY=${{ secrets.TOKEN }}" >> .env
- name: Build UI
  run: yarn build
```

**Validation:**

```bash
# Push fix, wait for CI
git commit -m "fix(ci): set API token before build"
git push

# Result: 42/42 tests now pass in CI! ✅
# Pass rate: 54% → 80% (26% improvement from ONE fix!)
```

**Documentation Created:**


### Issue #2: API Timeouts (41 tests hanging 30s each)

**Apply Tutorial 2.3 (AbortController):**

```typescript
// File: src/lib/strapi-api/base.ts

// Before: No timeout (hangs forever)
const response = await fetch(url)

// After: 30s timeout with AbortController
const controller = new AbortController()
const timeoutId = setTimeout(() => controller.abort(), 30000)

try {
  const response = await fetch(url, { signal: controller.signal })
  clearTimeout(timeoutId)
  // ... rest of code
} catch (error) {
  clearTimeout(timeoutId)
  if (error.name === "AbortError") {
    throw new Error(`Request timeout after 30000ms`)
  }
  throw error
}
```

**Result:** 41 tests no longer hang. Pass rate: **80% → 86%** (+6%)

### Issue #4: GDPR Checkboxes (10 tests, 30% failure rate)

**Apply Tutorial 2.2 (Polling Click Pattern):**

```typescript
// Before: Direct click (race condition)
await page.click('[role="checkbox"]')
await expect(submitButton).toBeEnabled() // Fails!

// After: Label click + polling
export async function checkGDPRCheckboxIfPresent(page: Page) {
  const label = page.locator('label[for="gdpr-consent"]')
  await label.click()

  // Poll for state change
  await page.waitForFunction(
    () =>
      document.getElementById("gdpr-consent")?.getAttribute("data-state") ===
      "checked"
  )

  // Verify button enabled
  const submitButton = page.locator('button[type="submit"]')
  await expect(submitButton).toBeEnabled()
}
```

**Result:** 10/10 tests pass consistently. Pass rate: **92% → 94%** (+2%)

```typescript
export async function safeSeed() {

    console.error("   This prevents accidental data loss.")

  await seedPages()
  await seedNavigation()
}
```

## Common Pitfalls in Test Suite Rescue

### ❌ Pitfall #1: Random Fixes

```
Bad: "Let me try increasing all timeouts to 60s"
Result: Masks problems, doesn't fix root cause

Good: "21 tests fail with toast timeout - investigate selector reliability"
Result: Find root cause (role attribute inconsistency), fix properly
```

### ❌ Pitfall #2: No Prioritization

```
Bad: Fix easiest issues first (feels productive but low impact)
Result: 10 hours → 5% improvement

Good: Fix highest-impact issues first (CI auth → 26% improvement)
Result: 2 hours → 26% improvement
```

### ❌ Pitfall #3: Fixing Symptoms Not Causes

```
Bad: "This test fails, let me add retry logic"
Result: Test passes but still flaky, retry masks issue

Good: "WHY does this test fail? Check trace files..."
Result: Find root cause (React state timing), fix properly
```

### ❌ Pitfall #4: Not Documenting

```
Bad: Fix everything, don't document, forget how in 6 months
Result: Next person faces same issues

Good: Document each fix with problem/solution/prevention
Result: Knowledge preserved, patterns reusable
```
