## Understanding the Problem

### The Missing Timeout

```javascript
// ❌ PROBLEM: No timeout (hangs indefinitely)
async function fetchPageData(slug) {
  const response = await fetch(`http://localhost:1337/api/pages/${slug}`)
  return response.json()
}

// What happens when server is slow:
// 1. fetch() starts request
// 2. Server takes 45 seconds to respond (overloaded)
// 3. Playwright test timeout (30s) fires first
// 4. Test fails with generic "Test timeout exceeded"
// 5. No indication the problem is the API call
```

**Key limitation:** The `fetch()` API **has no built-in timeout parameter**.

This is different from older libraries:

```javascript
// Axios has built-in timeout
axios.get("/api/data", { timeout: 5000 })

// jQuery AJAX has built-in timeout
$.ajax({ url: "/api/data", timeout: 5000 })

// fetch() has NO timeout option ❌
fetch("/api/data", { timeout: 5000 }) // timeout ignored!
```

## Solution: AbortController Pattern

### Step 1: Understanding AbortController

`AbortController` is a browser API (and Node.js 15+) that allows canceling fetch requests:

```javascript
// Create a controller
const controller = new AbortController()

// Pass signal to fetch
fetch("/api/data", { signal: controller.signal })

// Cancel the request
controller.abort() // fetch() throws AbortError
```

**Key concepts:**

- **Controller:** Object that manages abort signal
- **Signal:** Property passed to `fetch()` to link the request
- **Abort:** Method to cancel the request

### Step 2: Basic Timeout Implementation

```javascript
// ✅ Add timeout with AbortController
async function fetchWithTimeout(url, timeoutMs = 10000) {
  // Create abort controller
  const controller = new AbortController()

  // Set timeout to abort request
  const timeoutId = setTimeout(() => {
    controller.abort()
  }, timeoutMs)

  try {
    // Make request with abort signal
    const response = await fetch(url, {
      signal: controller.signal,
    })

    // ✅ CRITICAL: Clear timeout on success
    clearTimeout(timeoutId)

    return response
  } catch (error) {
    // ✅ CRITICAL: Clear timeout on error too
    clearTimeout(timeoutId)

    // Check if error was from timeout
    if (error.name === "AbortError") {
      throw new Error(`Request timeout after ${timeoutMs}ms`)
    }

    // Re-throw other errors
    throw error
  }
}
```

**Why clear timeout in both paths?**

- Success path: Request completed, timer no longer needed
- Error path: Request failed, timer no longer needed
- Without cleanup: Timer stays active, wastes memory

### Step 3: Production-Ready Implementation

Here's the actual implementation from our Strapi API client:

```typescript
// File: apps/ui/src/lib/strapi-api/base.ts

export default abstract class BaseStrapiClient {
  public async fetchAPI(
    path: string,
    params: Record<string, any> = {},
    requestInit?: RequestInit,
    options?: CustomFetchOptions
  ) {
    const { url, headers } = await this.prepareRequest(
      path,
      params,
      requestInit
    )

    // Create AbortController for timeout
    const controller = new AbortController()
    const timeoutMs = 30000 // 30 seconds
    const timeoutId = setTimeout(() => controller.abort(), timeoutMs)

    try {
      const response = await fetch(url, {
        ...requestInit,
        signal: controller.signal, // ← Link abort signal
        headers: {
          ...requestInit?.headers,
          ...headers,
        },
      })

      // ✅ Clear timeout on success
      clearTimeout(timeoutId)

      // Parse response
      const { json, text } = await this.parseResponse(response)

      if (text) {
        const appError = {
          name: "Invalid response format",
          message: text,
          status: response.status,
        }
        console.error("[BaseStrapiClient] Error:", appError)
        throw new Error(JSON.stringify(appError))
      }

      if (!response.ok) {
        const { error } = json
        const appError = {
          name: error?.name,
          message: error?.message,
          status: response.status,
        }
        console.error("[BaseStrapiClient] API Error:", appError)
        throw new Error(JSON.stringify(appError))
      }

      return json
    } catch (error: any) {
      // ✅ Clear timeout on error
      clearTimeout(timeoutId)

      // Handle abort (timeout)
      if (error.name === "AbortError") {
        const appError = {
          name: "Request Timeout",
          message: `Strapi API request to ${url} timed out after ${timeoutMs}ms`,
          status: 408, // Request Timeout HTTP status
        }
        console.error("[BaseStrapiClient] Timeout:", appError)
        throw new Error(JSON.stringify(appError))
      }

      // Re-throw other errors
      throw error
    }
  }
}
```

**Key improvements over basic version:**

✅ **Structured error objects** (name, message, status)  
✅ **Logging** (helps debugging in dev and production)  
✅ **HTTP 408 status code** (standard Request Timeout)  
✅ **Detailed error messages** (includes URL and timeout value)  
✅ **Preserves other errors** (network errors, JSON parse errors)

## Reusability Guide

### Pattern Works for Any Fetch Call

This isn't specific to Strapi or Next.js. Use it anywhere:

**Client-side API calls:**

```javascript
async function fetchUserData(userId) {
  const controller = new AbortController()
  const timeoutId = setTimeout(() => controller.abort(), 5000)

  try {
    const response = await fetch(`/api/users/${userId}`, {
      signal: controller.signal,
    })
    clearTimeout(timeoutId)
    return response.json()
  } catch (error) {
    clearTimeout(timeoutId)
    if (error.name === "AbortError") {
      throw new Error("User data request timed out")
    }
    throw error
  }
}
```

**Server-side API calls (Next.js API routes):**

```javascript
// app/api/proxy/route.ts
export async function GET(request) {
  const controller = new AbortController()
  const timeoutId = setTimeout(() => controller.abort(), 10000)

  try {
    const response = await fetch("https://external-api.com/data", {
      signal: controller.signal,
    })
    clearTimeout(timeoutId)
    const data = await response.json()
    return Response.json(data)
  } catch (error) {
    clearTimeout(timeoutId)
    if (error.name === "AbortError") {
      return Response.json(
        { error: "External API timeout" },
        { status: 504 } // Gateway Timeout
      )
    }
    throw error
  }
}
```

**Third-party API integrations:**

### Configurable Timeout Helper

Create a reusable wrapper:

```typescript
// lib/fetch-with-timeout.ts

interface FetchOptions extends RequestInit {
  timeout?: number // Custom timeout in ms
}

export async function fetchWithTimeout(
  url: string,
  options: FetchOptions = {}
): Promise<Response> {
  const { timeout = 10000, ...fetchOptions } = options

  const controller = new AbortController()
  const timeoutId = setTimeout(() => controller.abort(), timeout)

  try {
    const response = await fetch(url, {
      ...fetchOptions,
      signal: controller.signal,
    })
    clearTimeout(timeoutId)
    return response
  } catch (error: any) {
    clearTimeout(timeoutId)

    if (error.name === "AbortError") {
      throw new Error(`Request to ${url} timed out after ${timeout}ms`)
    }

    throw error
  }
}

// Usage:
const response = await fetchWithTimeout("/api/data", { timeout: 5000 })
const data = await response.json()
```

## Common Pitfalls

### ❌ Pitfall #1: Forgetting to Clear Timeout

```javascript
// Bad: Timeout keeps running after request completes
async function fetchData(url) {
  const controller = new AbortController()
  setTimeout(() => controller.abort(), 10000)

  const response = await fetch(url, { signal: controller.signal })
  // ❌ No clearTimeout() - memory leak!
  return response.json()
}

// Good: Always clear timeout
async function fetchData(url) {
  const controller = new AbortController()
  const timeoutId = setTimeout(() => controller.abort(), 10000)

  try {
    const response = await fetch(url, { signal: controller.signal })
    clearTimeout(timeoutId) // ✅ Cleanup
    return response.json()
  } catch (error) {
    clearTimeout(timeoutId) // ✅ Cleanup in error path too
    throw error
  }
}
```

### ❌ Pitfall #2: Not Handling AbortError

```javascript
// Bad: Generic error handling
try {
  await fetchWithTimeout("/api/data")
} catch (error) {
  console.error("Request failed:", error)
  // User sees: "Request failed: AbortError" (not helpful)
}

// Good: Check error type
try {
  await fetchWithTimeout("/api/data")
} catch (error) {
  if (error.name === "AbortError") {
    console.error("Request timed out - server may be overloaded")
  } else {
    console.error("Request failed:", error)
  }
}
```

### ❌ Pitfall #3: Too Short Timeout

```javascript
// Bad: Timeout too short for normal API calls
const controller = new AbortController()
setTimeout(() => controller.abort(), 1000) // 1 second
// Normal API call takes 2-3s → always times out!

// Good: Reasonable timeout based on expected response time
const controller = new AbortController()
setTimeout(() => controller.abort(), 10000) // 10 seconds
// Allows normal responses, catches truly hanging requests
```

### ❌ Pitfall #4: Reusing AbortController

```javascript
// Bad: Reusing same controller
const controller = new AbortController()

await fetch("/api/users", { signal: controller.signal })
await fetch("/api/posts", { signal: controller.signal }) // ❌ Wrong!

// Good: Create new controller per request
const controller1 = new AbortController()
await fetch("/api/users", { signal: controller1.signal })

const controller2 = new AbortController()
await fetch("/api/posts", { signal: controller2.signal })
```

## Advanced: Multiple Concurrent Requests

Handle timeouts for parallel requests:

```typescript
async function fetchAllPageData() {
  const slugs = ["home", "about", "contact"]

  const promises = slugs.map((slug) => {
    const controller = new AbortController()
    const timeoutId = setTimeout(() => controller.abort(), 10000)

    return fetch(`/api/pages/${slug}`, { signal: controller.signal })
      .then((res) => {
        clearTimeout(timeoutId)
        return res.json()
      })
      .catch((error) => {
        clearTimeout(timeoutId)
        if (error.name === "AbortError") {
          console.error(`${slug} timed out`)
          return null // Graceful degradation
        }
        throw error
      })
  })

  // Wait for all (some may be null if timed out)
  const results = await Promise.all(promises)
  return results.filter(Boolean) // Remove nulls
}
```
