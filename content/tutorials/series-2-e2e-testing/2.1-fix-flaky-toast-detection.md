## Problem Statement

Your Playwright E2E tests for toast notifications fail randomly—sometimes they pass, sometimes they fail with the exact same code. You're using `page.getByRole('status')` to find Radix UI toast components, but your test suite shows a frustrating 50% pass rate.

**Symptoms:**

- Tests pass locally but fail in CI
- Same test fails on re-run without code changes

## Understanding the Problem

### The Flaky Role-Based Selector

```typescript
// ❌ FLAKY: Role-based selector (fails 50% of the time)
import { test, expect } from "@playwright/test"

test("contact form shows success toast", async ({ page }) => {
  await page.goto("/contact")

  // Fill form
  await page.fill('[name="name"]', "John Doe")
  await page.fill('[name="email"]', "john@example.com")
  await page.fill('[name="message"]', "Test message")

  // Submit
  await page.click('button[type="submit"]')

  // ❌ THIS FAILS RANDOMLY!
  await expect(page.getByRole("status")).toBeVisible({ timeout: 5000 })
})
```

**Why it fails:**

1. **ARIA role inconsistency:** Radix UI doesn't guarantee `role="status"` across versions
   - Radix UI v1.2.x uses `role="status"`
   - Radix UI v1.3.x might use `role="alert"`
   - Future versions might use no role at all
2. **Multiple elements match:** Page might have multiple `role="status"` elements

   - Loading spinners
   - Announcement regions
   - Screen reader notifications

3. **Timing issues:** Toast element might exist before `role` attribute is added

### Debugging with Trace Viewer

When a test fails, Playwright creates trace files. Let's analyze one:

```bash
# Run test with tracing
npx playwright test contact-form.spec.ts --trace on

# Open trace viewer when test fails
npx playwright show-trace test-results/contact-form/trace.zip
```

**Key observations in trace:**

1. Navigate to the failed assertion timestamp
2. Inspect DOM snapshot—toast **IS visible** in the UI
3. Check attributes—`role="status"` might be missing or different
4. Look at element text—**always consistent**: "Thank you for contacting us!"

**Critical insight:** Text content is stable. ARIA roles are not.

## Solution: Text-Based Locator Pattern

### Step 1: Create Reliable Text-Based Locator

Instead of searching by role, search by the **actual text content** users see:

```typescript
// ✅ RELIABLE: Text-based locator (100% pass rate)
test("contact form shows success toast", async ({ page }) => {
  await page.goto("/contact")

  await page.fill('[name="name"]', "John Doe")
  await page.fill('[name="email"]', "john@example.com")
  await page.fill('[name="message"]', "Test message")
  await page.click('button[type="submit"]')

  // Wait for toast with success text
  await expect(page.locator("text=/thank you|success|submitted/i")).toBeVisible(
    { timeout: 5000 }
  )
})
```

**Why this works:**

✅ **Version-independent:** Text doesn't change with library updates  
✅ **User-centric:** Tests what users actually see  
✅ **Flexible regex:** Matches text variations (`/thank you|success/i`)  
✅ **Case-insensitive:** `i` flag handles "Success" vs "success"  
✅ **Future-proof:** No dependency on internal implementation details

### Step 2: Make It More Specific

Generic text patterns can match unintended elements. Be more specific:

```typescript
// Good: Specific success message
await expect(page.locator("text=/thank you for contacting us/i")).toBeVisible({
  timeout: 5000,
})

// Better: Target toast container first, then text
const toast = page.locator('[class*="Toast"], [data-radix-toast]')
await expect(toast.locator("text=/thank you/i")).toBeVisible({ timeout: 5000 })

// Best: Use data-testid for toast container (if you control the component)
const toast = page.locator('[data-testid="success-toast"]')
await expect(toast).toBeVisible({ timeout: 5000 })
```

### Step 3: Extract Reusable Test Helper

Don't repeat yourself. Create a helper function used across all tests:

```typescript
// File: tests/utils/toast-helpers.ts

import { Page, expect } from "@playwright/test"

/**
 * Waits for a success toast to appear with optional specific text
 *
 * @param page - Playwright page object
 * @param expectedText - Optional specific text to look for (default: generic success patterns)
 * @param timeout - Max wait time in ms (default: 5000)
 *
 * @example
 * await waitForSuccessToast(page); // Generic success detection
 * await waitForSuccessToast(page, 'Email sent successfully'); // Specific message
 */
export async function waitForSuccessToast(
  page: Page,
  expectedText?: string,
  timeout = 5000
): Promise<void> {
  // Default patterns cover common success messages
  const pattern = expectedText
    ? new RegExp(expectedText, "i")
    : /thank you|success|submitted|confirmed|sent successfully/i

  const toast = page.locator(`text=${pattern}`)
  await expect(toast).toBeVisible({ timeout })

  console.log(`✅ Success toast detected: "${await toast.textContent()}"`)
}

/**
 * Waits for an error toast to appear
 */
export async function waitForErrorToast(
  page: Page,
  expectedText?: string,
  timeout = 5000
): Promise<void> {
  const pattern = expectedText
    ? new RegExp(expectedText, "i")
    : /error|failed|invalid|required|could not/i

  const toast = page.locator(`text=${pattern}`)
  await expect(toast).toBeVisible({ timeout })

  console.log(`❌ Error toast detected: "${await toast.textContent()}"`)
}
```

### Step 4: Use Helper in All Form Tests

Now update all your tests to use the helper:

```typescript

import { waitForSuccessToast, waitForErrorToast } from "./utils/toast-helpers"

test.describe("Contact Form", () => {
  test("successful submission shows success toast", async ({ page }) => {
    await page.goto("/contact")

    await page.fill('[name="name"]', "Jane Smith")
    await page.fill('[name="email"]', "jane@example.com")
    await page.fill('[name="message"]', "This is a test")

    await page.click('button[type="submit"]')

    // ✅ Clean, reusable pattern
    await waitForSuccessToast(page, "Thank you for contacting us")
  })

  test("validation error shows error toast", async ({ page }) => {
    await page.goto("/contact")

    // Submit without filling required fields
    await page.click('button[type="submit"]')

    await waitForErrorToast(page, "All fields are required")
  })
})
```

## Reusability Guide

### Pattern Works for Any Toast Library

This isn't Radix UI-specific. Text-based detection works universally:

**React Hot Toast:**

```typescript
await expect(page.locator("text=/success/i")).toBeVisible()
```

**Chakra UI Toast:**

```typescript
await expect(page.locator('[role="alert"] >> text=/confirmed/i')).toBeVisible()
```

**Custom Toast Component:**

```typescript
await expect(page.locator(".toast-container >> text=/done/i")).toBeVisible()
```

### Adapt for Different Message Types

```typescript
// Success variants
await waitForSuccessToast(page, "Saved successfully")
await waitForSuccessToast(page, "Profile updated")
await waitForSuccessToast(page, "Payment processed")

// Error variants
await waitForErrorToast(page, "Network error")
await waitForErrorToast(page, "Invalid credentials")
await waitForErrorToast(page, "Session expired")

// Warning/info (create similar helpers)
await waitForWarningToast(page, "Changes not saved")
await waitForInfoToast(page, "New version available")
```

### Multi-Language Support

If your app supports multiple languages:

```typescript
export async function waitForSuccessToast(
  page: Page,
  locale: "en" | "es" | "fr" = "en"
): Promise<void> {
  const patterns = {
    en: /success|thank you|confirmed/i,
    es: /éxito|gracias|confirmado/i,
    fr: /succès|merci|confirmé/i,
  }

  await expect(page.locator(`text=${patterns[locale]}`)).toBeVisible()
}
```

## Common Pitfalls

### ❌ Pitfall #1: Overly Generic Patterns

```typescript
// Bad: Matches too many elements
await expect(page.locator("text=/success/i")).toBeVisible()
// Could match: "Success rate: 95%", "Successful login", page titles, etc.

// Good: Be specific
await expect(page.locator("text=/form submitted successfully/i")).toBeVisible()
```

### ❌ Pitfall #2: Not Waiting Long Enough

```typescript
// Bad: Too short timeout
await waitForSuccessToast(page, "Success", 1000) // API might take 2s

// Good: Reasonable timeout for API calls
await waitForSuccessToast(page, "Success", 5000)
```

### ❌ Pitfall #3: Forgetting Case Insensitivity

```typescript
// Bad: Case-sensitive (fragile)
await expect(page.locator("text=Success!")).toBeVisible()
// Breaks if text changes to "success!" or "SUCCESS!"

// Good: Case-insensitive regex
await expect(page.locator("text=/success!/i")).toBeVisible()
```

### ❌ Pitfall #4: Not Checking Toast Disappears

```typescript
// Incomplete: Toast might persist from previous test
test("second form submission", async ({ page }) => {
  await page.goto("/contact")
  await fillAndSubmit(page)

  // Might match toast from PREVIOUS test!
  await waitForSuccessToast(page)
})

// Complete: Wait for toast to disappear first
test("second form submission", async ({ page }) => {
  await page.goto("/contact")

  // Ensure no toast from previous test
  await expect(page.locator("text=/success/i")).not.toBeVisible()

  await fillAndSubmit(page)
  await waitForSuccessToast(page)
})
```

## Advanced: Enhanced Toast Helper

For production use, enhance the helper with better error messages and debugging:

```typescript
export async function waitForSuccessToast(
  page: Page,
  expectedText?: string,
  options: { timeout?: number; debug?: boolean } = {}
): Promise<void> {
  const { timeout = 5000, debug = false } = options

  const pattern = expectedText
    ? new RegExp(expectedText, "i")
    : /thank you|success|submitted|confirmed/i

  const toast = page.locator(`text=${pattern}`)

  try {
    await expect(toast).toBeVisible({ timeout })

    if (debug) {
      const text = await toast.textContent()
      console.log(`✅ Success toast detected: "${text}"`)
    }
  } catch (error) {
    // Enhanced error message with debugging help
    const pageContent = await page.content()
    const hasToastContainer =
      pageContent.includes("ToastViewport") ||
      pageContent.includes("toast-container")

    console.error("❌ Toast detection failed!")
    console.error(`   Expected pattern: ${pattern}`)
    console.error(`   Toast container exists: ${hasToastContainer}`)
    console.error(`   Timeout: ${timeout}ms`)
    console.error(
      "   💡 Try running with --debug flag and checking trace viewer"
    )

    throw error
  }
}
```
