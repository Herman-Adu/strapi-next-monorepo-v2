## Problem Statement

Your E2E tests fail intermittently when clicking GDPR checkboxes built with Radix UI. The checkbox _looks_ checked visually, but the submit button remains disabled. Tests fail with timeout errors waiting for buttons to enable.

**Symptoms:**

- Test clicks checkbox successfully (no error)
- Visual inspection shows checkbox is checked
- Submit button stays disabled (test times out)
- Re-running test sometimes passes, sometimes fails (~30% failure rate)
- Error: `expect(submitButton).toBeEnabled: Timeout 5000ms exceeded`

**Why This Matters:**
GDPR consent is legally required for EU users. Form submissions without valid consent tracking expose your organization to GDPR violations. Tests must reliably validate this critical user flow.

This issue blocked **10 critical tests** in our suite, including contact forms, newsletter signups, and account creation flows.

## Understanding the Problem

### The Race Condition

```typescript
// ❌ FLAKY: Direct checkbox click (fails ~30% of the time)
import { test, expect } from "@playwright/test"

test("GDPR checkbox enables submit button", async ({ page }) => {
  await page.goto("/contact")

  // Fill form fields
  await page.fill('[name="name"]', "John Doe")
  await page.fill('[name="email"]', "john@example.com")

  // Submit button is disabled initially
  const submitButton = page.locator('button[type="submit"]')
  await expect(submitButton).toBeDisabled()

  // Click checkbox
  await page.click('[data-state="unchecked"]')

  // ❌ THIS FAILS: Button still disabled!
  await expect(submitButton).toBeEnabled({ timeout: 5000 })
  // Error: Timeout 5000ms exceeded
})
```

**Root causes:**

1. **React State Propagation Delay:**

   - Click registers visually (CSS updates immediately)
   - React `onChange` handler fires asynchronously
   - Component state updates in next render cycle
   - Submit button re-renders with new `disabled` value
   - Total delay: 100-500ms depending on system load

2. **Event Handler Attachment Timing:**

   - Checkbox may render before event handler attached
   - Fast test clicks before React hooks initialized
   - Click registers but no state change occurs

3. **Radix UI Internal State Management:**
   - Radix components manage internal state separately from React
   - State synchronization happens asynchronously
   - `data-state` attribute updates after internal reconciliation

### Inspecting the DOM Structure

Radix UI renders checkboxes with this structure:

```html
<label for="gdpr-consent" class="flex items-center gap-2">
  <button
    role="checkbox"
    data-state="unchecked"
    ←
    State
    attribute
    id="gdpr-consent"
    aria-checked="false"
    ←
    ARIA
    attribute
  >
    <span data-state="unchecked">
      ← Visual indicator
      <!-- Check icon when checked -->
    </span>
  </button>
  <span>I agree to the terms and conditions</span>
</label>
```

**Key observations:**

- `data-state` changes from "unchecked" → "checked"
- `aria-checked` changes from "false" → "true"
- Visual icon nested inside button
- **Label wraps entire component** (critical for accessibility)

## Solution: Label Click + Polling Verification

### Strategy Overview

Instead of:

1. Click button directly
2. Hope state updates immediately
3. Assert button enabled

We use:

1. **Click label** (better event propagation)
2. **Poll for state change** (verify update occurred)
3. **Retry on failure** (handle timing variations)
4. **Assert final state** (verify complete update chain)

### Step 1: Click Label Instead of Button

```typescript
// ❌ BAD: Click button directly (small target, event issues)
await page.click('[role="checkbox"]')

// ✅ GOOD: Click label (accessibility pattern, larger target)
await page.click('label[for="gdpr-consent"]')
```

**Why this works better:**

✅ **Larger click target:** Entire label area is clickable (better UX)  
✅ **Standard HTML behavior:** Label clicks auto-toggle associated input  
✅ **Event propagation:** Browser fires all necessary events automatically  
✅ **Accessibility:** Matches how screen readers and keyboard navigation work  
✅ **React-friendly:** onChange handler reliably fires with label clicks

### Step 2: Poll for State Change

```typescript
// ✅ RELIABLE: Poll until state changes (handles async updates)
async function waitForCheckboxState(
  page: Page,
  checkboxId: string,
  expectedState: "checked" | "unchecked",
  timeout = 5000
): Promise<void> {
  await page.waitForFunction(
    ({ id, state }) => {
      const checkbox = document.getElementById(id)
      return checkbox?.getAttribute("data-state") === state
    },
    { id: checkboxId, state: expectedState },
    { timeout }
  )
}

// Usage:
await page.click('label[for="gdpr-consent"]')
await waitForCheckboxState(page, "gdpr-consent", "checked")
```

**How polling works:**

1. `page.waitForFunction` runs JavaScript in browser context
2. Checks condition repeatedly (every ~100ms by default)
3. Returns when condition true OR timeout reached
4. Handles async React state updates automatically

### Step 3: Create Reusable Helper with Retry Logic

```typescript
// File: tests/utils/checkbox-helpers.ts

import { Page, expect } from "@playwright/test"

/**
 * Checks GDPR checkbox if present on the page
 * Uses polling retry pattern to handle React state propagation
 *
 * @param page - Playwright page object
 * @param checkboxId - ID of the checkbox to check (default: tries multiple patterns)
 * @param maxAttempts - Max retry attempts (default: 5)
 * @returns true if checkbox found and checked, false if not present
 */
export async function checkGDPRCheckboxIfPresent(
  page: Page,
  checkboxId?: string,
  maxAttempts = 5
): Promise<boolean> {
  // Try multiple possible IDs (defensive coding for different forms)
  const possibleIds = checkboxId
    ? [checkboxId]
    : [
        "gdpr-consent",
        "contact-gdpr-consent",
        "newsletter-gdpr-consent",
        "terms-consent",
      ]

  for (const id of possibleIds) {
    const label = page.locator(`label[for="${id}"]`)
    const exists = (await label.count()) > 0

    if (!exists) continue // Try next ID

    console.log(`✓ Found GDPR checkbox: ${id}`)

    // Retry logic to handle race conditions
    for (let attempt = 1; attempt <= maxAttempts; attempt++) {
      try {
        // Step 1: Wait for label to be visible and clickable
        await expect(label).toBeVisible({ timeout: 2000 })

        // Step 2: Click label (accessibility pattern)
        await label.click()
        console.log(`  Attempt ${attempt}: Clicked label`)

        // Step 3: Poll for state change (handles React async updates)
        await page.waitForFunction(
          (checkboxId) => {
            const checkbox = document.getElementById(checkboxId)
            return checkbox?.getAttribute("data-state") === "checked"
          },
          id,
          { timeout: 2000 }
        )

        console.log(`  ✓ State changed to "checked"`)

        // Step 4: Verify submit button enabled (complete validation)
        const submitButton = page.locator('button[type="submit"]')
        await expect(submitButton).toBeEnabled({ timeout: 2000 })

        console.log(
          `✅ GDPR checkbox checked successfully (attempt ${attempt})`
        )
        return true // Success!
      } catch (error) {
        if (attempt === maxAttempts) {
          console.error(
            `❌ Failed to check GDPR checkbox after ${maxAttempts} attempts`
          )
          throw error
        }

        console.log(`  Attempt ${attempt} failed, retrying in 500ms...`)
        await page.waitForTimeout(500)
      }
    }
  }

  console.log("⚠️  No GDPR checkbox found (optional on this form)")
  return false // Checkbox not present (not an error)
}
```

### Pattern Works for Any State-Dependent UI

This polling pattern applies beyond checkboxes:

**Radio buttons:**

```typescript
async function selectRadioOption(page: Page, name: string, value: string) {
  const label = page.locator(
    `label:has(input[name="${name}"][value="${value}"])`
  )
  await label.click()

  // Poll for state
  await page.waitForFunction(
    ({ name, value }) => {
      const radio = document.querySelector(
        `input[name="${name}"][value="${value}"]`
      )
      return radio?.checked === true
    },
    { name, value },
    { timeout: 3000 }
  )
}
```

### Multi-Language GDPR Text

If checkbox label text varies by locale:

```typescript
export async function checkGDPRCheckboxByText(
  page: Page,
  locale: "en" | "es" | "fr" = "en"
): Promise<boolean> {
  const labelTexts = {
    en: /I agree to.*terms/i,
    es: /Acepto los.*términos/i,
    fr: /J'accepte les.*conditions/i,
  }

  const label = page.locator(`label:has-text("${labelTexts[locale]}")`)
  const exists = (await label.count()) > 0

  if (!exists) return false

  await label.click()

  // Find associated checkbox (might not have predictable ID)
  const checkbox = await label.locator('[role="checkbox"]')
  const checkboxId = await checkbox.getAttribute("id")

  if (checkboxId) {
    await waitForCheckboxState(page, checkboxId, "checked")
  }

  return true
}
```

## Common Pitfalls

### ❌ Pitfall #1: Clicking Button Instead of Label

```typescript
// Bad: Small click target, event issues
await page.click('[role="checkbox"]')

// Good: Accessibility pattern, reliable events
await page.click('label[for="gdpr-consent"]')
```

### ❌ Pitfall #2: Not Verifying State Changed

```typescript
// Bad: Assume click worked
await page.click('label[for="gdpr-consent"]')
await page.click('button[type="submit"]') // Might fail!

// Good: Verify state before proceeding
await page.click('label[for="gdpr-consent"]')
await waitForCheckboxState(page, "gdpr-consent", "checked")
await page.click('button[type="submit"]') // Guaranteed to work
```

### ❌ Pitfall #3: Too Short Timeout

```typescript
// Bad: Timeout too short for slow CI
await page.waitForFunction(checkState, { timeout: 1000 })

// Good: Reasonable timeout for async updates
await page.waitForFunction(checkState, { timeout: 5000 })
```

### ❌ Pitfall #4: Not Handling Optional Checkboxes

```typescript
// Bad: Throws error if checkbox not present
await checkGDPRCheckbox(page) // Error: Checkbox not found

// Good: Returns boolean, doesn't throw
const wasChecked = await checkGDPRCheckboxIfPresent(page)
if (wasChecked) {
  console.log("GDPR consent provided")
}
```

### ❌ Pitfall #5: Checking Already-Checked State

```typescript
// Bad: No idempotency check
export async function checkGDPRCheckbox(page: Page, id: string) {
  await page.click(`label[for="${id}"]`) // Might UNCHECK if already checked!
}

// Good: Check current state first
export async function checkGDPRCheckbox(page: Page, id: string) {
  const checkbox = page.locator(`#${id}`)
  const currentState = await checkbox.getAttribute("data-state")

  if (currentState === "checked") {
    console.log("Already checked, skipping")
    return
  }

  await page.click(`label[for="${id}"]`)
  await waitForCheckboxState(page, id, "checked")
}
```

## Advanced: Complete Helper with Edge Cases

Production-ready helper handling all edge cases:

```typescript
// File: tests/utils/checkbox-helpers.ts (complete version)

import { Page, expect } from "@playwright/test"

interface CheckboxOptions {
  /** Max retry attempts (default: 5) */
  maxAttempts?: number
  /** Delay between retries in ms (default: 500) */
  retryDelay?: number
  /** Throw error if checkbox not found (default: false) */
  throwIfNotFound?: boolean
  /** Expected final state (default: 'checked') */
  expectedState?: "checked" | "unchecked"
}

export async function checkGDPRCheckboxIfPresent(
  page: Page,
  checkboxId?: string,
  options: CheckboxOptions = {}
): Promise<boolean> {
  const {
    maxAttempts = 5,
    retryDelay = 500,
    throwIfNotFound = false,
    expectedState = "checked",
  } = options

  // Try multiple ID patterns
  const possibleIds = checkboxId
    ? [checkboxId]
    : [
        "gdpr-consent",
        "contact-gdpr-consent",
        "newsletter-gdpr-consent",
        "terms-consent",
      ]

  for (const id of possibleIds) {
    const label = page.locator(`label[for="${id}"]`)
    const exists = (await label.count()) > 0

    if (!exists) continue

    const checkbox = page.locator(`#${id}`)
    const currentState = await checkbox.getAttribute("data-state")

    // Already in expected state
    if (currentState === expectedState) {
      console.log(`✓ Checkbox already in state: ${expectedState}`)
      return true
    }

    // Attempt to toggle state
    for (let attempt = 1; attempt <= maxAttempts; attempt++) {
      try {
        await expect(label).toBeVisible({ timeout: 2000 })
        await label.click()

        // Poll for state change
        await page.waitForFunction(
          ({ id, state }) => {
            const el = document.getElementById(id)
            return el?.getAttribute("data-state") === state
          },
          { id, state: expectedState },
          { timeout: 2000 }
        )

        // Verify submit button state if checking (enabling submit)
        if (expectedState === "checked") {
          const submitButton = page.locator('button[type="submit"]')
          await expect(submitButton).toBeEnabled({ timeout: 2000 })
        }

        console.log(
          `✅ Checkbox set to "${expectedState}" (attempt ${attempt})`
        )
        return true
      } catch (error) {
        if (attempt === maxAttempts) {
          throw new Error(
            `Failed to set checkbox to "${expectedState}" after ${maxAttempts} attempts`
          )
        }
        await page.waitForTimeout(retryDelay)
      }
    }
  }

  // Checkbox not found
  if (throwIfNotFound) {
    throw new Error(
      `GDPR checkbox not found (tried IDs: ${possibleIds.join(", ")})`
    )
  }

  console.log("⚠️  No GDPR checkbox found (optional on this form)")
  return false
}

// Convenience wrapper for checking (most common use case)
export async function checkGDPRCheckbox(page: Page, checkboxId?: string) {
  return checkGDPRCheckboxIfPresent(page, checkboxId, {
    expectedState: "checked",
  })
}

// Convenience wrapper for unchecking
export async function uncheckGDPRCheckbox(page: Page, checkboxId?: string) {
  return checkGDPRCheckboxIfPresent(page, checkboxId, {
    expectedState: "unchecked",
  })
}
```
